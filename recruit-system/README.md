# リクルート判定システム（TOHOシネマズ新宿版）

**応募者の名前と属性を入れたら、面接台本のとおりの報告書を作るアプリ**です。
面接者は面接台本（スタッフ面接チェックリスト 2026-10-08 版）の順に入力するだけで、A4 1 枚の「面接チェックリスト報告」（結果・必須条件・確認点・面接メモの要約。電子印・最終合否つき）になります。
報告書は 1 ファイルの HTML で、社内スレッドに添付 → 副支配人がブラウザで開いて最終合否と電子印 → 再出力、の往復ができます。

既定は **台本モード**（3 ステップ）です。従来の 4 ステップ（留意点の申し送り・シフト貢献度の 2 軸判定）は **詳細モード** として残してあり、設定の先頭「運用モード」で切り替えられます（他劇場向け。末尾の「詳細モード」）。

## 使い方（配布）

1. `dist/toho-recruit-judge.html` を PC に置き、ブラウザ（Edge / Chrome）で開く
2. 左のメニュー「報告書の作成」で 3 ステップを進める（トップバーの画面名は「面接チェックリスト報告」、サイドバーの見出しは「手順」。詳細モードでは従来どおり「応募者判定」「判定ステップ」）
   1. **① 応募者** … 1 枚のカード・3 行だけ（氏名だけ必須。あとは分かる範囲で）。PC の画面（1280×800 以上）ならスクロールせずに「面接チェックリストへ進む →」まで見える
      - 1 行目: 氏名（必須）・年齢・性別・区分（高校1〜3年生／大学…／フリーター／主婦／ダブルワーク／その他）。学生の区分のときだけ末尾に卒業予定年月
      - 2 行目: 面接日（既定は今日）・面接担当者（名簿から選択。③ の押印欄「面接対応者」の初期選択になる）・応募した求人（「通常」「短期」のボタン）
      - 3 行目: タクシー可否・料金（自由記述。例: 可・2,500円）・メモ（任意）
      - 消極属性（短期希望／朝～12時のみ）は 2026-10-13 に削除しました（両モードとも。旧いファイルに残っていても読み込めます）
   2. **② 面接チェックリスト** … 台本の順に ① 勤務条件 10分 → ② 継続性・報連相 3分 → ③ 仕事内容の説明 10分 → ④ 集団行動特性 8分 → ⑤ 逆質問 最大10分（合否連絡を含む）。上部に ① で入れた属性を 1 行（氏名・区分・年齢・求人・タクシー・面接日・担当。読み取り専用・「応募者を編集」で ① へ）と目次（sticky。済・不一致・面接評価の点数をライブ表示）
      - **必須条件**（土日を含む週3日以上・5時間以上／指定繁忙期間すべて可）は 一致／不一致（未回答は「未確認」）。1 つでも不一致なら赤い案内が出て「⑤ 逆質問へ」で面接を打ち切れる
      - 説明は「説明済み」のチェック（※短期求人のみの項目は短期求人のとき強調）。【説明】【合否連絡】の見出しの右の「すべて説明した」で一括チェック（※短期求人のみ の項目は求人が短期のときだけ。もう一度押すと「すべて外す」）、質問は質問文を大きく表示してメモ欄に回答を書く、記入欄（土日いずれか／両日・出勤不可な繁忙・短期／長期の希望・契約開始日の希望・初回契約終了・OPEN／25時までの可否）
      - **確認事項／確認点**（7 項目）を ○△× と一言メモで評価し、最後に**面接者の総合判断**（採用／保留／不採用）と面接所見
      - 入力のチェックでは止めない（未入力は報告書に「確認事項」として出る）。「報告書へ進む →」
   3. **③ 報告書** … 開いた時点で判定し、A4 1 枚の「面接チェックリスト報告」の紙プレビュー（白地。ダークモードでも白。印刷と同じ等倍の文字で見せ、1280px・1366px など右サマリーの横に紙が入らない画面では右サマリーを紙の下に回す）を表示。その下に押印欄（初期対応者〔応募受付を行った担当者〕／面接対応者／最終確認）と「最終合否」、操作ボタン「🖨 A4 で印刷」「💾 報告書を保存（HTML）」。押印・合否を変えると紙プレビューも描き直す
3. 右のサマリーには 氏名・属性（区分・年齢・性別。短期求人ならそのチップ）・面接日・担当・必須条件（一致／不一致／未確認）・採点（○△× の集計と点数）・総合判断・結果・押印状況・最終合否・保存状態を出す
4. 「保存（HTML）」で応募者ごとに 1 ファイル。「読み込み」で続きから再開できる（旧形式のファイルや詳細モードで保存したファイルも読める）
   - ③ を開かずに ① や ② から保存・A4 印刷しても、その時点の入力で判定して報告書に結果を入れる（チェックリストが未入力でも上長最終判断要＋確認事項として出る）。③ を開くと同じ判定になる。読み込むと保存したステップ（①／②）から再開する
   - 総合判断が未入力のまま保存すると「（総合判断が未入力です）」の警告を出す（保存は止めない）

### 結果（推奨）の決まり方（台本モード）

- 必須条件に 1 つでも「不一致」→ **不採用推奨**（台本どおり。設定 `checklist.mustFailResult` で「上長最終判断要」に変更可）
- それ以外は **面接者の総合判断のとおり**: 採用 → 採用推奨、保留 → 上長最終判断要、不採用 → 不採用推奨。総合判断が未入力なら上長最終判断要＋警告
- 必須条件の「未確認」は警告だけ（`mustUnknownResult = 'review'` で採用推奨に留めない）。総合判断の上限 `checklist.overallCaps` は厳しくしたときだけ効く（結果を下げる方向のみ）
- 確認点の ○△× は面接評価（○2・△1・×0 ＋総合判断 2/1/0、既定 16 点満点、帯 高 ≥ 70%・中 ≥ 40%）として報告書に載せる。結果は変えない（「採用」なのに × があれば警告 1 行）
- シフト貢献度・2 軸マトリクス・留意点は台本モードでは使わない

## 報告書（HTML）と最終合否

アプリの判定（採用推奨／上長最終判断要／不採用推奨）とは別に、最終確認者（副支配人）が「採用」「不採用」のスタンプで最終合否を記録します。

1. 面接者がアプリの ③ 報告書で押印欄「面接対応者」に電子印を押し、「報告書を保存（HTML）」→ 社内スレッドに添付
2. 副支配人がその HTML をブラウザで開く。常に**「報告書」表示**（A4 の紙プレビュー＋「最終合否」と押印欄）で開き、上部の「詳細」でヘッダー・ダッシュボード（面接評価〔確認点〕・必須条件・総合判断・結果）・応募者情報・面接チェックリスト・採用可否判定・応募者の管理を表示する
3. 「最終合否」で担当者を選び「採用」または「不採用」を押す → 合否スタンプ（採用＝朱・不採用＝藍、日付と劇場名入り）が紙の結果ストリップの右端に出る。押印欄「最終確認」が未押印なら同じ担当者の電子印も自動で押される
4. 「押印を保存」で再出力 → スレッドに添付。ファイル名の末尾に `_採用` / `_不採用`（例: `応募者_山田_太郎_2026-10-10_採用.html`。押し直すと付け替え、「取消」で外れる）
5. 再出力したファイルをアプリの「読み込み」で開くと、合否・押印ごと ③ 報告書と右サマリー（例「採用・笹川」）に引き継がれる。合否が判定と食い違う（採用 × 不採用推奨など）ときは注記を 1 行出すだけで止めない

- 「取消」は合否だけを消し、自動で押した「最終確認」の印は残る（押印は押印欄の「取消」で消す）
- 担当者名簿は設定の「応募者の管理（押印）」で編集。合否の UI は同じ節の「最終合否（採用／不採用のスタンプ）」で ON/OFF・表示名・連動する押印欄・ファイル名の接尾辞を変えられる

## 印刷（A4 面接チェックリスト報告 1 枚）

- アプリ: ③ 報告書の「🖨 A4 で印刷」、② の「🖨 面接チェックリスト報告（A4）」、トップバーの「🖨 印刷」、ブラウザの印刷（Ctrl+P）のどれでも面接チェックリスト報告になる（判定が無ければ印刷の前に現在の入力で判定する）
  - 制限: 旧形式（10 項目×5 点）の記録（面接チェックリスト未入力）を開いているとき、および判定画面以外（設定・使い方）での Ctrl+P は画面全体の印刷になる（旧形式の記録では 🖨 ボタンは案内を出して印刷しない）
- 保存 HTML: 「面接チェックリスト報告（A4）」ボタン、または報告書表示のまま Ctrl+P。「レポート全体」は「詳細」の内容（台本モードの節だけ）を印刷する
- 中身（2026-10-14〜。副支配人「煩雑すぎて頭に入ってこない。わかりやすく、かつ1ページで」）: 誰を・どう判断し・何が気になるかを 10 秒で掴める **A4 1 枚の要約**。上から
  1. ヘッダー帯（面接チェックリスト報告・台本の版・劇場名・作成日）
  2. 応募者（氏名を大きく＋区分・年齢・性別・卒業予定／面接日・担当・応募した求人・タクシー可否・料金。空の項目は省く）
  3. **結果ストリップ**: 結果（採用推奨＝緑／上長最終判断要＝琥珀／不採用推奨＝赤。判定前は「未実施」）・総合判断・必須条件（すべて一致／不一致 n）・確認点（16/16点・○△× の数）、右端に最終合否（未押印は点線枠）。調整があればその下に 1 行（例「必須条件の不一致により「不採用推奨」に固定」）
  4. 必須条件（○一致／×不一致／－未確認・土日勤務可否・出勤不可な繁忙）｜勤務条件の確認（短期／長期の希望・契約開始日・初回契約終了・OPEN／25時の可否）
  5. 確認点 7 行（①〜⑤・名前・○△× の丸バッジ・メモ 1 行。未入力の行も出す）
  6. 面接メモ（記入があるものだけ。質問の回答は「短い名前：回答」で 2 行まで・面接所見・① のメモ）
  7. 説明・連絡 1 行（説明済み ① 4/4 ・ ② 3/3 …／合否連絡 採用時 ☑ ／ 不合格 ☐。※短期求人のみ の説明は求人が短期のときだけ数える）
  8. 押印行（初期対応者／面接対応者／最終確認）
- 台本の説明文・質問文・確認点の補足・空の記入欄は載せない。台本の全文（質問文・説明のチェック・記入欄・メモ・点）は保存 HTML の「詳細」の「面接チェックリスト」節と「レポート全体」の印刷に残る
- 必ず 1 ページ: 本文が A4 を超えたら自動で詰める（`.cl-compact` 本文 9px・面接所見は 10 行まで〔質問の回答は 2 行のまま〕→ `.cl-compact-q1` 質問の回答 1 行 → `.cl-compact-2` 質問の回答を省いて「詳細」を案内 → 最後は縮小〔縮小後に測り直す〕）。上限は押印欄の件数（押印行の段数）で決める。メモが「…」で切れたら「全文は保存 HTML の「詳細」表示に」の 1 行。紙プレビューも印刷と同じ見た目。白黒でも読める記号
- 回答が無くても印刷できる（白紙の台本として面接前に使える）

## 設定（劇場ルール）

- **運用モード**（先頭）: 台本モード（既定）／詳細モード。保存すると判定ステップを作り直し、Step1 に戻る（入力中の応募者のデータは保持）
- 台本モードで使う節: 劇場情報・応募者の属性（区分・性別・卒業予定年月）・面接チェックリスト（台本の文言・項目・確認点・必須条件の扱い・面接評価の帯〔高・中・低〕の境界・総合判断の表示名・応募した求人）・結果文言（台本モード）・応募者の管理（押印・最終合否）・書き出し／読み込み。台本モードの「面接チェックリスト」節には、応募情報からの自動表示の選択肢や詳細モードだけの判定設定（要判断の留意点・高校生の方針）は出さない（値は保持。後者は「詳細モードの設定」の「採用可否判定の調整（詳細モード）」）
- 詳細モードの節（入力の段階・繁忙期・高校生・申し送りルール・シフト貢献度・2 軸判定など）は「詳細モードの設定（台本モードでは使いません）」に畳んである（台本モードのままでも編集・保存できる。左の目次の「詳細モードの設定」を押すと開いて移動する）
- 設定はブラウザの localStorage（キー `recruit.profile.v1`、`schemaVersion: 2`、`mode: 'script' | 'full'`）に保存。`mode` の無い既存の設定は台本モードとして開き、1 回だけ案内を出して保存する。他劇場・他端末へは JSON を書き出して読み込む
- 応募者データはブラウザに残らない（保存した HTML のみが記録）

- 配布ファイルの生成: `node build.js`
- テスト（すべて exit 0 で合格）:

  ```
  cd recruit-system
  node tests/rules.test.js           # 単体テスト（Node だけで動く）
  node build.js && node tests/e2e.js # 通しテスト（Playwright + Chromium が必要）
  ```

## 設計方針

- **ロジックとルールの分離**: `rules.js` は劇場名・しきい値・文言を一切持たず、`profile` を引数に受け取る。法令値（深夜 22:00〜翌5:00、年少者 18 歳）だけはコード定数 `LAW`
- **入力の段階** = セクションの構造（どのフィールドがどのセクションか）は `rules.js` の `INPUT_SECTIONS`、既定の段階は `profile.inputStages`。`stageOf` は `inputStages` が無い・不正なら `'pre'`（従来どおり）。面接時のセクションが未入力なだけの留意点は `buildHandoff` が `deferred` / `aggregate` の印を付け、Step2 の一覧から外して Step3・判定で扱う（条件・判定は変えない）
- **留意点ルール** = `rules.js` の `CONDITIONS[id]`（条件）＋ `profile.handoffRules[]`（ON/OFF・重要度・文言）
  - 重要度: `block` 要判断（採用担当が面接実施・採用の可否を判断）/ `warn` 要確認（面接時に確認）/ `info` 共有
  - カテゴリ: 法令・高校生・全般・繁忙期/休日・オールナイト・深夜帯・専門学校生・外国籍・入力の整合。法令ルールは OFF・重要度変更不可（文言は編集可）
- **採用可否判定** = 面接評価とシフト貢献度をそれぞれ得点率（%）で帯に分け、マトリクスで決める。項目数や配点を変えても閾値を調整しなくてよい
- **面接チェックリスト** = 台本は `profile.checklist`（セクション → ブロック〔must 必須条件 / fields 記入欄 / explain 説明 / question 質問 / rating 確認点 / notify 合否連絡 / note 注記〕→ 項目）のデータ。判定に効くのは must・rating・総合判断だけで、ほかは記録用。回答は `record.checklist`（項目 id をキーにした `values` / `notes`・`overall`・`header`）、保存時点の台本を `record.checklistDef` に残し、レポートは保存時の文言で出す。`rules.interviewModel` が面接評価の項目の出どころ（チェックリスト／旧 10 項目）を決め、`evaluateHiring` 以降の 2 軸判定は共通
- **保存形式** = 人が読める HTML レポート＋ `<script type="application/json" id="recruit-record">` に元データ（`schemaVersion: 2`、保存時点の貢献度スナップショットを含む）を埋め込み。見た目を変えても読込が壊れない。レポート本体はアプリと同じデザイントークン（カード・バッジ・バー・マトリクス表）で、先頭に判定サマリーを置き、A4 印刷にも対応（`storage.js` の `reportCss`）
- **運用モード** = `profile.mode`（'script' 既定／'full'）。アプリの分岐は `R.isScriptMode(profile)` の 1 か所、保存 HTML と A4 報告は保存時の `record.mode`（`R.isScriptRecord`。mode の無い旧レコードは詳細扱い）。内部のステップキー（`state.step`・`data-step`・`record.step`）は台本モードでも 1 / 3 / 4 で、表示番号だけ ①②③。台本モードの判定は `rules.evaluateScript`（総合判断が基準）、詳細モードは `evaluateHiring`（2 軸）。台本モードでは留意点を作り直さず、`checklistAuto` は自動の見込みを出さない（手入力のみ）
- **後方互換** = 旧プロファイル・旧保存ファイルは `storage.normalizeProfile` / `app.applyRecord` で補完。既存のルール id・applicant のパス・`PROFILE_KEY` は変えない

## 詳細モード（他劇場向け）

設定の「運用モード」で「詳細モード」にすると、従来の 4 ステップになります（フェーズ1〜5 の機能。`docs/SPEC.md`・`docs/SPEC-stages.md`・`docs/SPEC-checklist.md`・`docs/SPEC-report.md`）。

1. **応募情報**（採用担当が入力）… 基本情報・通勤・勤務条件（曜日・時間・週の日数・勤務期間）・面接者への申し送りコメント。繁忙期・深夜帯・オールナイト・かけもち・外国籍の詳細などは面接時に確認（設定「入力の段階」で切替）
2. **面接者への申し送り** … 留意点（要判断・要確認・共有）と強み、面接で確認すること、シフト貢献度の見込み。コピー・申し送りシート（A4 1 枚）
3. **面接チェックリスト** … 台本の ①〜⑤ ＋「面接で確認する項目」（シフト条件。貢献度に反映）。応募情報からの自動表示（見込み）あり
4. **採用可否判定** … 面接評価 × シフト貢献度の 2 軸マトリクス。必須条件の不一致・要判断の未確認・高校生の方針などで下げる方向に調整

保存 HTML も従来どおり（応募時の情報・申し送りコメント・留意点・面接で確認した情報・シフト貢献度・面接チェックリスト・採用可否判定・応募者の管理、申し送りシートの印刷）。台本モードで保存した記録を詳細モードで読むと、応募情報の詳細は空のまま Step1 で入力できます。逆に詳細モードの記録を台本モードで読むと、表示されない項目もデータとして保持されます。

### 判定モデル（詳細モード）

- **面接評価**（面接チェックリスト）: 確認事項／確認点の ○ 2・△ 1・× 0 点と、面接者の総合判断 採用 2・保留 1・不採用 0 点の得点率。既定は確認点 7 ＋総合判断 1 で **16 点満点**（確認点を設定で増減すると満点が変わる。得点率なので境界は直さなくてよい）。帯 高 ≥ 70%（12 点以上）/ 中 ≥ 40%（7 点以上）/ 低

  | 例（16 点満点） | 点 | % | 帯 |
  | --- | --- | --- | --- |
  | 全○＋採用 | 16 | 100 | 高 |
  | ○4 △3＋採用 | 13 | 81.3 | 高 |
  | ○4 △2 ×1＋採用 | 12 | 75 | 高 |
  | ○3 △3 ×1＋採用 | 11 | 68.8 | 中 |
  | 全△＋採用 | 9 | 56.3 | 中 |
  | ○1 △3 ×3＋保留 | 6 | 37.5 | 低 |

  2026-10 以前に保存した 10 項目×5 点の面接評価のファイルは、チェックリストに入力しない限り旧方式（旧 10 項目・50 点満点）で再判定する
- **必須条件ゲート**: 必須条件が 1 つでも「不一致」なら、点数にかかわらず**不採用推奨**（台本「必須条件が不一致なら不採用」。設定 `checklist.mustFailResult` で「上長最終判断要」に変更可）。「未確認」のまま判定したときは警告のみ（`mustUnknownResult = 'review'` で採用推奨に留めない）
- **総合判断の上限**: 総合判断「保留」→ 上長最終判断要まで、「不採用」→ 不採用推奨まで（`checklist.overallCaps`。各 'none' で無効）
- **シフト貢献度**: 8 項目の合計（既定 100 点）
  繁忙期 30・土日 15・祝日 5・オールナイト 15・クローズ/深夜 10・オープン 5・週の勤務日数 10・勤務期間 10。△ は満点の 5 割。帯 高 ≥ 60% / 中 ≥ 35% / 低（帯は丸めた得点率で判定）
- **2 軸マトリクス**（行 = 面接、列 = 貢献度。既定）

  | 面接＼貢献 | 高 | 中 | 低 |
  | --- | --- | --- | --- |
  | 高 | 採用推奨 | 採用推奨 | 上長最終判断要 |
  | 中 | 上長最終判断要 | 上長最終判断要 | 不採用推奨 |
  | 低 | 不採用推奨 | 不採用推奨 | 不採用推奨 |

- **調整（下げる方向のみ）**: 必須条件の不一致（先頭で適用）・未確認（設定時）、シフト条件が未確定（面接のみで判定し採用推奨に留めない）、総合判断（保留・不採用）、要判断の留意点が未確認、高校生の方針（原則対象外・例外条件未充足）、法令の要判断。マトリクスの結果と最終結果・理由は Step4 と保存レポートに併記。調整で結果が下がったときは本文を「点数上は〇〇ですが、下記の理由により△△とします」にし、マスの注記は出さない。必須条件の不一致で不採用推奨に固定したときは、点数にかかわらず本文を「必須条件（…）が一致しないため…不採用推奨とします」にする（打ち切りで面接評価が 0% でも、それを理由にしない）
- `features.contribution = false` にすると従来どおり面接評価のみで判定（他劇場の旧プロファイルはこの状態で移行）
