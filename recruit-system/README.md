# リクルート判定システム（TOHOシネマズ新宿版）

アルバイト採用の判断基準を統一するための判定アプリです。
水戸内原版 ver4.4 をベースに、**面接後の採用可否判定を中核**に据え、面接前は「面接者への留意点の申し送り」として再設計しました。
劇場固有のルールはすべて「劇場プロファイル」に切り出してあり、設定画面から編集・JSON で持ち運びできます。

## 使い方（配布）

1. `dist/toho-recruit-judge.html` を PC に置き、ブラウザ（Edge / Chrome）で開く
2. 「応募者判定」で 4 ステップを進める
   1. **応募情報**（採用担当が入力・目安 2〜3 分）… 面接に進めるかの判断に使う項目だけを入力する
      - 基本情報（氏名* 性別 年齢* 区分* 卒業予定年月。高校生は「原則対象外」の表示と高3の例外条件）・外国籍に該当するか（該当する／しない）
      - 通勤（通勤方法* 通勤時間* 最寄り駅）
      - 勤務条件（勤務可能曜日* 勤務希望時間* 週の最低勤務日数・週の最大勤務日数* 勤務期間*）。面接に進めるかの判断に使う「週何日・時間帯・勤務期間」は必須。週の最大勤務日数の必須は設定「入力の段階」の「週の最大勤務日数を Step1 の必須にする」（既定 ON）で外せる（外すと空欄でも進め、面接で確認する）
      - **面接者への申し送りコメント**（自由記述。申し送りの冒頭に出る。面接者向けのフリーコメントはこれ 1 つが基本で、Step2 の「追記（申し送りコメントの補足・任意）」は空なら閉じた折りたたみ）
      - 繁忙期・土日祝の頻度、深夜帯（22時以降）の可否と帰宅手段、オールナイト、かけもち、外国籍の詳細、学生の卒業後の継続、希望部署・応募経路は**面接時に確認する項目**。応募フォームなどで分かっていれば、閉じた折りたたみ「面接前に分かっている項目があれば入力（任意）」から先に入力できる（必須ではない）
   2. **面接者への申し送り** … 申し送りコメント → 応募者 → **「面接で確認すること」**（面接時のセクションごとに 未入力／入力済み、判定前に入力が必要なもの）→ 留意点（要判断・要確認・共有。面接時の項目が未入力なだけの留意点は出さない）と強み → シフト貢献度の見込み → チェック・コピーして共有
   3. **面接評価** … 面接者が採点し、「面接で確認する項目」で面接時の項目をすべて表示・入力する（Step1 で先に入力した値も表示・修正できる）。判定に必要なシフト条件（*）が未確認だと判定に進めない。面接で入力した内容から出た留意点（繁忙期× など）は同じカードの「面接で入力した内容から出た留意点」でチェックでき、Step2 に戻らずに判定できる。入力しないまま確認済みにしたい留意点は「未入力のまま判定する場合の留意点」でチェックする
   4. **採用可否判定** … 面接評価 × シフト貢献度の 2 軸マトリクスで 採用推奨 / 上長最終判断要 / 不採用推奨。面接で確認しないまま残った留意点には「面接で確認」の印
3. 「保存（HTML）」で応募者ごとに 1 ファイル保存。レポートは「応募時の情報」と「面接で確認した情報」（面接前に保存したときは「面接前に分かっている情報（未確認）」）に分かれ、「読み込み」で再開できる（旧形式 v1 のファイル・段階分け導入前のファイルも読める）
4. 「設定（劇場ルール）」で文言・しきい値・繁忙期・配点・マトリクスを編集。他劇場へは JSON を書き出して展開
   - **「入力の段階（面接前に入力／面接時に確認）」**で、セクションごとに Step1 で入力するか面接時（Step3）に確認するかを切り替えられる（基本情報・勤務条件・申し送りコメントは常に面接前）。「既定に戻す」「すべて面接前に入力（従来の並び）」のボタン、週の最大勤務日数を Step1 の必須にする・折りたたみを常に開く、の設定もここ
5. 留意点・申し送りは A4 1 枚に印刷できる。Step2 の「申し送りシート（A4）」、保存レポート上部の「申し送りシート（A4 1枚）」で、応募情報・申し送りコメント・留意点・面接で確認する項目・押印欄だけをコンパクトに印刷する（留意点が多いときは 2 段組み）
6. 保存レポート末尾の「応募者の管理」で、初期対応者・面接対応者・最終確認の 3 枠に担当者の日付印（ハンコ）を押せる。アプリの Step2/Step4 でも押印でき、レポート上で押した場合は「押印を保存」で再出力して元のファイルと置き換える。未保存の押印があるままレポートを閉じようとすると確認が出る。担当者名簿は設定の「応募者の管理（押印）」で編集

設定はブラウザの localStorage（キー `recruit.profile.v1`、中身は `schemaVersion: 2`）に保存されます。応募者データはブラウザに残りません（保存した HTML のみが記録です）。

## 新宿の運用ルール（既定値。すべて設定画面で変更可）

| 項目 | 内容 |
| --- | --- |
| 高校生 | **原則対象外**（`highschoolPolicy.mode = 'exceptionOnly'`）。例外は「高校3年生・進路（進学）決定済み・卒業後も当劇場で継続」の 3 条件を満たす人のみ。高1・高2は区分の選択肢と赤いアラートで「原則対象外」と表示。条件を満たさない場合も入力は止めず、留意点「要判断」＋判定は採用推奨に留めない（`holdOnHighschoolException`）。高3で進路が**就職**の場合は不採用推奨（ほぼ短期採用のため。`rejectCareerPaths`）、その他（浪人・未定など）・進路未決定は上長最終判断要 |
| 繁忙期 | 3連休・GW・夏休み・お盆・シルバーウィーク・年末年始・春休みの 7 期間（増減可）。期間ごとに ○△× と出られる日数（合計／週あたり／1回あたり）を入力。3連休・GW・夏休み・お盆・年末年始は「重点」（× で要判断） |
| 土日祝 | 土日の出勤頻度（毎週両日／毎週どちらか／隔週／月1）と祝日の可否 |
| オールナイト | 深夜帯（22時以降のクローズ）とは別軸で ○△× と頻度を入力。18歳未満は労基法61条により不可（法令ルールは OFF 不可）。18歳以上でも高校在学中は運用で不可（`nightRestricted`） |
| 終電 | 希望シフトの最も遅い終了＋余裕（既定 15 分）と終電時刻を突合（5:00 前の終電は翌日扱い） |
| 入力の段階 | 面接前（Step1）: 基本情報・高3の例外条件・外国籍の該当・通勤・勤務条件・申し送りコメント。面接時（Step3）: 繁忙期・土日祝／深夜帯／オールナイト／かけもち／外国籍の詳細／学生の卒業後の継続／希望部署・応募経路（`inputStages`。詳細は `docs/SPEC-stages.md`）。段階は画面と申し送りの見せ方だけで、判定の結果は変わらない |

## 判定モデル

- **面接評価**: 10 項目 × 5 点の得点率。帯 高 ≥ 70% / 中 ≥ 40% / 低
- **シフト貢献度**: 8 項目の合計（既定 100 点）
  繁忙期 30・土日 15・祝日 5・オールナイト 15・クローズ/深夜 10・オープン 5・週の勤務日数 10・勤務期間 10。△ は満点の 5 割。帯 高 ≥ 60% / 中 ≥ 35% / 低（帯は丸めた得点率で判定）
- **2 軸マトリクス**（行 = 面接、列 = 貢献度。既定）

  | 面接＼貢献 | 高 | 中 | 低 |
  | --- | --- | --- | --- |
  | 高 | 採用推奨 | 採用推奨 | 上長最終判断要 |
  | 中 | 上長最終判断要 | 上長最終判断要 | 不採用推奨 |
  | 低 | 不採用推奨 | 不採用推奨 | 不採用推奨 |

- **調整（下げる方向のみ）**: シフト条件が未確定（面接のみで判定し採用推奨に留めない）、要判断の留意点が未確認、高校生の方針（原則対象外・例外条件未充足）、法令の要判断、総合判断の足切り（既定 OFF）。マトリクスの結果と最終結果・理由は Step4 と保存レポートに併記。調整で結果が下がったときは本文を「点数上は〇〇ですが、下記の理由により△△とします」にし、マスの注記は出さない
- `features.contribution = false` にすると従来どおり面接評価のみで判定（他劇場の旧プロファイルはこの状態で移行）

## 開発

```
recruit-system/
  src/
    index.html          画面骨格
    styles.css          デザイントークン・レイアウト・ダークモード・印刷
    util.js             共通ユーティリティ（パス操作・テンプレート置換）
    stamp.js            日付印（ハンコ）の SVG。レポートにも関数ソースを埋め込んで使う
    config.default.js   劇場プロファイル既定値（新宿）＝ 選択肢・繁忙期・しきい値・留意点ルール・評価項目・貢献度・マトリクス・文言
    rules.js            判定エンジン（DOM 非依存の純関数）。法令定数 LAW・LOCKED_RULES もここ
    storage.js          HTML 保存・読込（JSON 埋め込み方式）、プロファイル保存・移行（normalizeProfile）・検証（validateProfile）
    settings.js         設定画面（data-bind によるプロファイル編集）
    app.js              画面制御（ステップ遷移・フォーム生成・右サマリー）
  build.js              src を 1 ファイルに結合 → dist/toho-recruit-judge.html
  dist/                 配布用（ビルド成果物。コミットする）
  tests/rules.test.js   判定エンジン・移行・検証の単体テスト（外部依存なし）
  tests/e2e.js          Playwright による通しテスト（docs/SPEC.md 9-2 の E1〜E12 ＋ E13・E14、docs/SPEC-stages.md 7-2 の E15〜E21、押印の E22）
  tests/fixtures/       旧形式（v1）の保存ファイル・プロファイル（移行テスト用）
  docs/SPEC.md          フェーズ2（高校生・繁忙期・オールナイト・2軸判定）の詳細仕様
  docs/SPEC-stages.md   フェーズ3（入力の段階分け: 面接前に入力／面接時に確認）の詳細仕様
  docs/HANDOFF.md       引き継ぎメモ（現状・決定事項・残 TODO）
  docs/reference/       旧版（水戸内原 ver4.4）の参照用コピー
```

- 開発中は `src/index.html` を直接ブラウザで開いても動きます
- 配布ファイルの生成: `node build.js`
- テスト（すべて exit 0 で合格）:

  ```
  cd recruit-system
  node tests/rules.test.js           # 単体テスト（Node だけで動く）
  node build.js && node tests/e2e.js # 通しテスト（Playwright + Chromium が必要）
  ```

  e2e は日時を 2026-10-10 に固定し、各確認を `PASS` / `FAIL` で出力します。FAIL が 1 件でもあるか、ページのエラーがあれば exit 1。スクリーンショットは `tests/shots/`（git 管理外）に出ます。
  段階分けのシナリオ: E15 Step1 は面接前の項目だけ → Step2「面接で確認すること」→ Step3 で入力して判定／E16 折りたたみで先行入力・区分の変更で「卒業後の継続」の置き場所が移る／E17 設定で段階を切り替える（Step1 に出る・外国籍の制約・一括ボタン・`requireDaysMax`・不正値の normalize）／E18 外国籍は該当だけ面接前（`#deferredItems`・Step4 の「面接で確認」）／E19 保存 → 読込（レポートの 2 章・`inputStages` のスナップショット・段階情報の無い旧 v2 レコード）／E20 面接で確認する項目の表示（外国籍「該当しない」・折りたたみの summary・未入力が残る間は「すべて確認済み」にしない・他劇場の旧プロファイル）／E21 Step3 で GW× などを入力 → Step3 の「面接で入力した内容から出た留意点」でチェック → Step2 に戻らずに 2軸判定、折りたたみで入れた外国籍の詳細を Step2 の応募者表に表示。E7 では旧形式（v1）ファイルの面接時の項目が Step3 と折りたたみに出ることも確認します。
  閉じた `<details>` の中身は Chromium で `offsetParent` が残るため、e2e の表示判定は `checkVisibility()` も使います。
  Playwright が `require('playwright')` で見つからない場合は `/opt/node-tools/node_modules/playwright` を使います。

## 設計方針

- **ロジックとルールの分離**: `rules.js` は劇場名・しきい値・文言を一切持たず、`profile` を引数に受け取る。法令値（深夜 22:00〜翌5:00、年少者 18 歳）だけはコード定数 `LAW`
- **入力の段階** = セクションの構造（どのフィールドがどのセクションか）は `rules.js` の `INPUT_SECTIONS`、既定の段階は `profile.inputStages`。`stageOf` は `inputStages` が無い・不正なら `'pre'`（従来どおり）。面接時のセクションが未入力なだけの留意点は `buildHandoff` が `deferred` / `aggregate` の印を付け、Step2 の一覧から外して Step3・判定で扱う（条件・判定は変えない）
- **留意点ルール** = `rules.js` の `CONDITIONS[id]`（条件）＋ `profile.handoffRules[]`（ON/OFF・重要度・文言）
  - 重要度: `block` 要判断（採用担当が面接実施・採用の可否を判断）/ `warn` 要確認（面接時に確認）/ `info` 共有
  - カテゴリ: 法令・高校生・全般・繁忙期/休日・オールナイト・深夜帯・専門学校生・外国籍・入力の整合。法令ルールは OFF・重要度変更不可（文言は編集可）
- **採用可否判定** = 面接評価とシフト貢献度をそれぞれ得点率（%）で帯に分け、マトリクスで決める。項目数や配点を変えても閾値を調整しなくてよい
- **保存形式** = 人が読める HTML レポート＋ `<script type="application/json" id="recruit-record">` に元データ（`schemaVersion: 2`、保存時点の貢献度スナップショットを含む）を埋め込み。見た目を変えても読込が壊れない。レポート本体はアプリと同じデザイントークン（カード・バッジ・バー・マトリクス表）で、先頭に判定サマリーを置き、A4 印刷にも対応（`storage.js` の `reportCss`）
- **後方互換** = 旧プロファイル・旧保存ファイルは `storage.normalizeProfile` / `app.applyRecord` で補完。既存のルール id・applicant のパス・`PROFILE_KEY` は変えない
