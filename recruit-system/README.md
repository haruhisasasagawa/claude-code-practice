# リクルート判定システム（TOHOシネマズ新宿版）

**応募者の名前と属性を入れたら、面接台本のとおりの報告書を作るアプリ**です。
面接者は面接台本（スタッフ面接チェックリスト 2026-10-08 版）の順に入力するだけで、A4 1 枚の「面接チェックリスト報告」（結果・必須条件・確認点・面接メモの要約。電子印・最終合否つき）になります。
報告書は 1 ファイルの HTML で、社内スレッドに添付 → 副支配人がブラウザで開いて最終合否と電子印 → 再出力、の往復ができます。

2026-10-14 に**面接に特化**しました（副支配人の指示「面接までの経緯はクリアしているので省いてよい」）。面接前の入力・判定の機能と押印欄 1 つを削除し、押印欄は面接対応者・最終確認の 2 つです（削除した機能は `docs/HANDOFF.md` の「削除済み機能」、削除前のコードはタグ `full-mode-last`）。

## 使い方（配布）

1. `dist/toho-recruit-judge.html` を PC に置き、ブラウザ（Edge / Chrome）で開く
2. 左のメニュー「報告書の作成」で 3 ステップを進める（トップバーの画面名は「面接チェックリスト報告」、サイドバーの見出しは「手順」）
   1. **① 応募者** … 1 枚のカード・3 行だけ（氏名だけ必須。あとは分かる範囲で）。PC の画面（1280×800 以上）ならスクロールせずに「面接チェックリストへ進む →」まで見える
      - 1 行目: 氏名（必須）・年齢・性別・区分（高校1〜3年生／大学1〜4年生／大学院生／専門学校生1〜3年生／フリーター／主婦・主夫／ダブルワーカー／その他）。学生の区分のときだけ末尾に卒業予定年月
      - 2 行目: 面接日（既定は今日）・面接担当者（名簿から選択。③ の押印欄「面接対応者」の初期選択になる）・応募した求人（「通常」「短期」のボタン）
      - 3 行目: タクシー可否・料金（自由記述。例: 可・2,500円）・メモ（任意）
   2. **② 面接チェックリスト** … 台本の順に ① 勤務条件 10分 → ② 継続性・報連相 3分 → ③ 仕事内容の説明 10分 → ④ 集団行動特性 8分 → ⑤ 逆質問 最大10分（合否連絡を含む）。上部に ① で入れた属性を 1 行（氏名・区分・年齢・求人・タクシー・面接日・担当。読み取り専用・「応募者を編集」で ① へ）と目次（sticky。済・不一致・面接評価の点数をライブ表示）
      - **必須条件**（土日を含む週3日以上・5時間以上／指定繁忙期間すべて可）は 一致／不一致（未回答は「未確認」）。1 つでも不一致なら赤い案内が出て「⑤ 逆質問へ」で面接を打ち切れる
      - 説明は「説明済み」のチェック（※短期求人のみの項目は短期求人のとき強調）。【説明】【合否連絡】の見出しの右の「すべて説明した」で一括チェック（※短期求人のみ の項目は求人が短期のときだけ。もう一度押すと「すべて外す」）、質問は質問文を大きく表示してメモ欄に回答を書く、記入欄（土日いずれか／両日・出勤不可な繁忙・短期／長期の希望・契約開始日の希望・初回契約終了・OPEN／25時までの可否）
      - **確認事項／確認点**（7 項目）を ○△× と一言メモで評価し、最後に**面接者の総合判断**（採用／保留／不採用）と面接所見
      - 入力のチェックでは止めない（未入力は報告書に「確認事項」として出る）。「報告書へ進む →」
   3. **③ 報告書** … 開いた時点で判定し、A4 縦の用紙 1 枚の「面接チェックリスト報告」（210×297mm。保存 HTML・印刷と同じ用紙。白地でダークモードでも白。押印行も用紙の中。印刷と同じ等倍の文字で見せ、1280px・1366px など右サマリーの横に用紙が入らない画面では右サマリーを用紙の下に回す）を表示。その下に押印欄（**面接対応者／最終確認** の 2 つ。2 列）と「最終合否」、操作ボタン「🖨 A4 で印刷」「💾 報告書を保存（HTML）」。押印・合否を変えると用紙も描き直す（用紙の欄はクリックしても何もしない。操作は下のカード）
3. 右のサマリーには 氏名・属性（区分・年齢・性別。短期求人ならそのチップ）・面接日・担当・必須条件（一致／不一致／未確認）・採点（○△× の集計と点数）・総合判断・結果・押印状況・最終合否・保存状態を出す
4. 「保存（HTML）」で応募者ごとに 1 ファイル。「読み込み」で続きから再開できる
   - ③ を開かずに ① や ② から保存・A4 印刷しても、その時点の入力で判定して報告書に結果を入れる（チェックリストが未入力でも上長最終判断要＋確認事項として出る）。③ を開くと同じ判定になる。読み込むと保存したステップ（①／②）から再開する
   - 総合判断が未入力のまま保存すると「（総合判断が未入力です）」の警告を出す（保存は止めない）
   - 2026-10-14 より前のファイル（v1・旧 10 項目の評価入りなど）もエラーなく読める。削除した機能のデータは読み込まず（toast で案内）、面接チェックリストの回答・押印（面接対応者・最終確認）・最終合否は引き継ぐ。旧い形式の記録は ② で開くので、面接チェックリストで評価し直す（回答と判定が入っている記録は ③ 報告書で開く）

### 結果（推奨）の決まり方

- 必須条件に 1 つでも「不一致」→ **不採用推奨**（台本どおり。設定 `checklist.mustFailResult` で「上長最終判断要」に変更可）
- それ以外は **面接者の総合判断のとおり**: 採用 → 採用推奨、保留 → 上長最終判断要、不採用 → 不採用推奨。総合判断が未入力なら上長最終判断要＋警告
- 必須条件の「未確認」は警告だけ（`mustUnknownResult = 'review'` で採用推奨に留めない）。総合判断の上限 `checklist.overallCaps` は厳しくしたときだけ効く（結果を下げる方向のみ）
- 確認点の ○△× は面接評価（○2・△1・×0 ＋総合判断 2/1/0、既定 16 点満点、帯 高 ≥ 70%・中 ≥ 40%）として報告書に載せる。結果は変えない（「採用」なのに × があれば警告 1 行）

  | 例（16 点満点） | 点 | % | 帯 |
  | --- | --- | --- | --- |
  | 全○＋採用 | 16 | 100 | 高 |
  | ○4 △3＋採用 | 13 | 81.3 | 高 |
  | ○4 △2 ×1＋採用 | 12 | 75 | 高 |
  | ○3 △3 ×1＋採用 | 11 | 68.8 | 中 |
  | 全△＋採用 | 9 | 56.3 | 中 |
  | ○1 △3 ×3＋保留 | 6 | 37.5 | 低 |

## 報告書（HTML）と最終合否

保存した HTML は **A4 縦の用紙 1 枚そのもの**です（2026-10-14〜。副支配人「出力の HTML は A4 たてがたをイメージ。その様式で印刷もしたい（別にしない）」。仕様は `docs/SPEC-a4.md`）。画面では灰色の背景に用紙を 1 枚表示し、そのまま印刷すると画面と同じ 1 枚になります。「詳細」表示（台本の全文）は無く、用紙の外に常設の操作パネルも置きません。

アプリの判定（採用推奨／上長最終判断要／不採用推奨）とは別に、最終確認者（副支配人）が「採用」「不採用」のスタンプで最終合否を記録します。

1. 面接者がアプリの ③ 報告書で押印欄「面接対応者」に電子印を押し、「報告書を保存（HTML）」→ 社内スレッドに添付
2. 副支配人がその HTML をブラウザで開く（A4 の用紙 1 枚。押せる欄はマウスを載せると薄い枠と「クリックで押印」「クリックで合否を押す」の案内が出る。案内は印刷されない）
3. 用紙の「最終合否」の欄（結果ストリップの右端）をクリック → 小さな窓で担当者を選び「採用」または「不採用」を押す（最終承認のパスワードがあるときは、先に窓でパスワードを入れる。下の「最終承認のパスワード」）→ 合否スタンプ（採用＝朱・不採用＝藍、日付と劇場名入り）が用紙に出る。押印欄「最終確認」が未押印なら同じ担当者の電子印も自動で押される。合否が判定と食い違う（採用 × 不採用推奨・不採用 × 採用推奨）ときは窓を開いたまま注記を 1 行出す（止めない）。押印欄（面接対応者／最終確認）も用紙の欄をクリックして同じ窓で押す・取り消す（名簿にない担当者は「名簿にない担当者（手入力）」で氏名を入れる）。窓は Esc・「閉じる」・窓の外のクリックで閉じる
4. 押印・合否を変えると画面の右下に「押印・合否を変更しました ［押印を保存］」のバーが出る（いちばん下までスクロールすれば用紙に重ならない）。「押印を保存」で再出力 → スレッドに添付。ファイル名の末尾に `_採用` / `_不採用`（例: `応募者_山田_太郎_2026-10-10_採用.html`。押し直すと付け替え、「取消」で外れる）。書き出し後は「保存しました（保存できなかったときは再保存）［再保存］［×］」（［×］でバーを閉じる）。保存せずに閉じようとすると確認が出る。書き出すファイルには窓・バーは残らない
5. 再出力したファイルをアプリの「読み込み」で開くと、合否・押印ごと ③ 報告書と右サマリー（例「採用・笹川」）に引き継がれる

- 「取消」は合否だけを消し、自動で押した「最終確認」の印は残る（押印は押印欄の窓の「取消」で消す）
- 「…」で切れたメモ（面接メモ・確認点のメモ）は、画面でクリックすると全文を窓に出す（質問の回答を省いた用紙では、案内の行をクリックするとすべてのメモ）。印刷は常に 1 枚（キーボードで操作した直後に印刷しても、欄のフォーカス枠は紙に出ない）
- 狭い画面（スマートフォンなど）では用紙ごと画面の幅に縮小して見せる（横スクロールなし。描画だけを縮めるので、行・折り返し・行数は印刷と同じ。印刷には影響しない）
- 担当者名簿は設定の「応募者の管理（押印）」で編集。合否の欄は同じ節の「最終合否（採用／不採用のスタンプ）」で ON/OFF・表示名・連動する押印欄・ファイル名の接尾辞を変えられる（OFF なら用紙に合否の欄を出さない）
- 2026-10-14 より前に保存した HTML（報告書／詳細の切替つき）もそのまま開け、アプリで読み込んで保存し直すと A4 の用紙になる

## 最終承認のパスワード

副支配人「最終承認の押印はパスワードが必要な感じの方がいいかもしれないね」（2026-10-14。仕様は `docs/SPEC-a4.md` 11 章）。

- 対象は **最終確認の押印・取消**（最終確認の欄〔`final`〕と、設定「押印欄と連動」の欄。「連動しない」・別の欄に変えても最終確認の欄は対象のまま）と **最終合否（採用／不採用）の決定・取消**。アプリの ③ 報告書と保存した HTML の両方。**面接対応者の押印には要らない**
- パスワードが設定されていてまだ入れていないとき、③ のカード（最終確認の押印欄・最終合否）は担当者の選択とボタンの代わりに「🔒 最終承認にはパスワードが必要です」とパスワード欄・［確認］を出す。保存した HTML では用紙の「最終確認」「最終合否」の欄をクリックした窓にパスワード欄が出る。違えば「パスワードが違います」の 1 行だけで何もしない（Enter でも確定）。正しければ**そのページを閉じる（読み込み直す）まで**続けて押せる（解錠の状態は localStorage にも書き出すファイルにも残さない＝書き出したファイルを開き直すとまた求める）
- 設定「応募者の管理（押印）」の「最終承認のパスワード」: 状態（設定済み／未設定）・［変更］（現在のパスワード〔設定済みのとき〕・新しいパスワード・確認）・［パスワードを外す］（現在のパスワードが要る）。変更は「設定を保存」で確定。プロファイル JSON の読み込みや「初期設定に戻す」でパスワードが変わる・外れるときも、現在のパスワードを求める（違えば・キャンセルなら読み込まない／戻さない）。パスワードがあるとき、「押印欄と連動」・最終合否のスタンプの ON/OFF・押印欄の構成（追加・削除・id）・押印欄の表示名を変えて「設定を保存」する（同じ変更を含む JSON を読み込む）ときも現在のパスワードを求める（押印欄の説明・名簿だけの変更には要らない。表示名を含めるのは、面接対応者の欄を「最終確認」と表示してパスワードなしに押した印を最終確認に見せられないようにするため）
- **パスワードそのものは保存しない**。設定・プロファイル JSON・保存 HTML には照合用の `management.finalLock = { salt, hash }`（`hash = sha256(salt + ':' + パスワード)`）だけを入れる。保存 HTML は**保存した時点のパスワード**で照合する（あとでアプリのパスワードを変えても、出したファイルは変わらない）
- パスワードの無いアプリ（公開版・パスワードを外した設定）でパスワード付きの保存 HTML を読み込むと、その記録の最終確認・最終合否は**ファイルのパスワード**で守り、保存し直したファイルにも同じパスワードを入れる（新規・別の記録に切り替えると外れる）。アプリにパスワードがあれば従来どおりアプリのパスワード
- **誤操作を防ぐための鍵**です。HTML をテキストで開いて書き換える人までは防げません
- 公開版（`dist/`）はパスワードなし。ローカル版（ロゴ・名簿入りの版）の初期パスワードは `local/final-password.txt` で決める（下の「ロゴ・名簿入りの版」。使い方の画面には「管理者に確認してください」とだけ出す）。ブラウザに保存済みの設定にパスワードの項目が無い・空なら、その版の初期パスワードを使う。Chrome などは file:// の保存を公開版とローカル版で共有するが、公開版で設定を保存してもローカル版のパスワードは外れない（外れるのは［パスワードを外す］で外したときだけ）。**公開版でパスワードの無い状態から（現在のパスワードなしに）決めたパスワード・読み込んだ JSON のパスワードも、ローカル版では使わない**（ローカル版は初期パスワード、またはローカル版で現在のパスワードを確かめて変えたパスワードのまま。設定には「初期パスワードからつながっている」印 `chain: true` を持つ）。ローカル版で決めたパスワードは公開版でも使い、公開版で現在のパスワードを確かめて変えればローカル版も新しいパスワードになる。パスワードの無いプロファイル JSON を読み込んでもパスワードは変わらない
- 別のタブ（ウィンドウ）で設定を保存・初期化すると、ほかのタブは最新の設定を読み込み直す（タブに戻ったとき・設定の保存や押印・報告書の保存〔HTML〕の直前にも確かめる）。古いタブのまま、パスワードなしで最終確認を押したり、新しいパスワードを古い設定で上書きしたり、古いパスワード（ロックなし）のファイルを書き出したりしない。設定画面で入力中のパスワードの欄は、別のタブでパスワード以外が保存されても閉じない

## 印刷（A4 面接チェックリスト報告 1 枚）

- アプリ: ③ 報告書の「🖨 A4 で印刷」、② の「🖨 面接チェックリスト報告（A4）」、トップバーの「🖨 印刷」、ブラウザの印刷（Ctrl+P）のどれでも ③ と同じ A4 の用紙 1 枚を印刷する（判定が無ければ印刷の前に現在の入力で判定する）。設定・使い方の画面での Ctrl+P は画面全体の印刷
- 保存 HTML: ブラウザの印刷（Ctrl+P）でそのまま用紙 1 枚（`@page` の余白 0。画面と同じ要素・寸法・文字組み。印刷のための切替はしない）。ブラウザの印刷設定の「余白」は「デフォルト」（または「なし」）、倍率は 100% のまま印刷する（用紙の余白は HTML が指定している）
- 中身（2026-10-14〜。副支配人「煩雑すぎて頭に入ってこない。わかりやすく、かつ1ページで」）: 誰を・どう判断し・何が気になるかを 10 秒で掴める **A4 1 枚の要約**。上から
  1. 見出し（白地に濃紺の下線。左にロゴ〔ロゴ入りの版だけ〕と「面接チェックリスト報告」、右に 台本の版 ／ 劇場名 ／ 作成日）
  2. 応募者（氏名を大きく＋区分・年齢・性別・卒業予定／面接日・担当・応募した求人・タクシー可否・料金。空の項目は省く）
  3. **結果ストリップ**: 結果（採用推奨＝緑／上長最終判断要＝琥珀／不採用推奨＝赤。判定前は「未実施」）・総合判断・必須条件（すべて一致／不一致 n）・確認点（16/16点・○△× の数）、右端に最終合否（未押印は点線枠）。調整があればその下に 1 行（例「必須条件の不一致により「不採用推奨」に固定」）
  4. 必須条件（○一致／×不一致／－未確認・土日勤務可否・出勤不可な繁忙）｜勤務条件の確認（短期／長期の希望・契約開始日・初回契約終了・OPEN／25時の可否）
  5. 確認点 7 行（①〜⑤・名前・○△× の丸バッジ・メモ 1 行。未入力の行も出す）
  6. **面接メモ・所見の枠**（2026-10-14〜。用紙の残りの高さいっぱい）: 記入があるもの（質問の回答は「短い名前：回答」で 2 行まで・面接所見・① のメモ）を上から並べ、その下（記入が無ければ枠全体）は手書き用の薄い点線の罫線（7.5mm 間隔）
  7. 説明・連絡 1 行（説明済み ① 4/4 ・ ② 3/3 …／合否連絡 採用時 ☑ ／ 不合格 ☐。※短期求人のみ の説明は求人が短期のときだけ数える）
  8. 押印行（面接対応者／最終確認。**用紙の内寸の下端**＝書類の最下段）
- 台本の説明文・質問文・確認点の補足・空の記入欄は載せない（台本の全文を出す「詳細」表示は 2026-10-14 に削除）
- 用紙を埋める（2026-10-14〜。「印刷すると空白が多くなる」への対応）: 内容が少ないときは**ゆったり**（`.cl-roomy` 本文 10.5px・行と確認点の行を広げる。面接メモ・所見の枠に 38mm 以上の罫線を残せるときだけ）。押印行は用紙の下端、空いた高さは面接メモ・所見の枠が取る
- 必ず 1 ページ: 用紙の内寸（281mm）に収まらなければ自動で詰める（ゆったり → 通常 → `.cl-compact` 本文 9px・面接所見は 10 行まで〔質問の回答は 2 行のまま〕→ `.cl-compact-q1` 質問の回答 1 行 → `.cl-compact-2` 質問の回答を省いて案内 1 行 → 最後は縮小〔縮小後に測り直す〕）。詰め方を決めたあと、「…」で切れたメモがあって面接メモ・所見の枠に罫線の空きが残っていれば、面接所見 → メモ → 質問の回答の順に行数を広げて空きを使う（全部入れば「…」と案内は消える。重いサンプルで面接所見 10 → 23 行）。上限は押印行を含めた内容の高さ 1052px（`CL_SHEET_LIMIT_PX`。内寸 ≒ 1062px から 10px の余裕。計測は `.cl-measure` で用紙いっぱいに伸ばさない状態の高さ）。保存 HTML は開いたときに計測して確定し、その状態のまま印刷する。メモが「…」で切れたら「「…」で切れたメモは、画面でクリックすると全文を表示します」の 1 行（アプリ ③ の紙では「保存した HTML の画面でクリックすると…」。③ の紙はクリックしても窓を出さない）。白黒でも読める記号
- 回答が無くても印刷できる（白紙の台本として面接前に使える）

## 設定（劇場ルール）

設定画面は 5 節です。

1. **劇場情報**: 劇場名・アプリ名・バージョン表記・フッター
2. **応募者の属性**: 区分（「値|グループ」。グループは学生〔highschool / university / vocational。① に卒業予定年月の欄を出す〕か、それ以外〔other〕か）・性別・卒業予定年月の表示
3. **面接チェックリスト**: 判定（必須条件の不一致・未確認のとき・総合判断の上限・不一致のとき案内するセクション・面接評価の帯〔高・中・低〕の境界）・総合判断の見出しと表示名・ヘッダー（担当と連動する押印欄・応募した求人）・台本（版・ページの見出しと説明・セクション・ブロック・項目の文言と増減・並べ替え・既定に戻す）
4. **応募者の管理（押印）**: 押印欄 2 つ（面接対応者・最終確認）の表示名と説明・担当者名簿・手入力の可否・最終合否（ON/OFF・表示名・連動する押印欄・ファイル名の接尾辞）・最終承認のパスワード（設定・変更・外す。上の「最終承認のパスワード」）
5. **書き出し／読み込み**: プロファイル JSON の書き出し・読み込み・初期設定に戻す

- 結果の文言（`texts`）は画面に出さない（JSON の書き出し／読み込みでだけ変更できる）
- 設定はブラウザの localStorage（キー `recruit.profile.v1`、`schemaVersion: 2`）に保存。キーは `schemaVersion, meta, features, management, options, evaluation, checklist, texts` の 8 つだけ。他劇場・他端末へは JSON を書き出して読み込む
- 2026-10-14 より前の設定は開いたときに正規化して保存し直す（削除した機能のキーと廃止した押印欄 `initial` を落とす。旧い運用モードの設定だったときは 1 回だけ toast で案内）。v1 形式の JSON は移行せず既定の設定にする（「古い形式のため既定の設定を使います」）
- 応募者データはブラウザに残らない（保存した HTML のみが記録）

## 設計方針

- **ロジックとルールの分離**: `rules.js` は劇場名・しきい値・文言を一切持たず、`profile` を引数に受け取る
- **面接チェックリスト** = 台本は `profile.checklist`（セクション → ブロック〔must 必須条件 / fields 記入欄 / explain 説明 / question 質問 / rating 確認点 / notify 合否連絡 / note 注記〕→ 項目）のデータ。判定に効くのは must・総合判断だけで、rating は面接評価（点数・帯）として報告し、ほかは記録用。回答は `record.checklist`（項目 id をキーにした `values` / `notes`・`overall`・`header`）、保存時点の台本を `record.checklistDef` に残し、レポートは保存時の文言で出す。面接評価は `rules.interviewModel(profile, cl)`、判定は `rules.evaluateScript`（総合判断が基準）
- **ステップの内部キー** = `state.step`・`data-step`・`record.step` は 1 / 3 / 4（表示は ①②③）。旧レコードの 2 は ① に読み替える
- **保存形式** = 人が読める HTML レポート＋ `<script type="application/json" id="recruit-record">` に元データ（`schemaVersion: 2`。キーは `kind, schemaVersion, savedAt, profile, step, applicant〔6 キー〕, checklist, checklistDef, interviewNotes, management, decision, judgment`）を埋め込み。見た目を変えても読込が壊れない。レポート本体は A4 縦の用紙 1 枚（画面と印刷で同じ要素・寸法。`storage.js` の `reportCss`・`checklistSheetCss`）
- **後方互換** = 旧プロファイルは `storage.normalizeProfile`（許可したキーだけ組み立てる）、旧保存ファイルは `storage.normalizeRecord`（応募者 6 キー・廃止した押印欄 `initial` を外す・旧い形式の印を返す）で読む。`PROFILE_KEY`・`schemaVersion`・面接チェックリストの項目 id は変えない
