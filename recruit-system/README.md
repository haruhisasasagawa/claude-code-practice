# リクルート判定システム（TOHOシネマズ新宿版）

**応募者の名前と属性を入れたら、面接台本のとおりの報告書を作るアプリ**です。
面接者は面接台本（スタッフ面接チェックリスト 2026-10-08 版）の順に入力するだけで、A4 1 枚の「面接チェックリスト報告」（結果・必須条件・確認点・面接メモの要約。電子印・最終合否つき）になります。
報告書は 1 ファイルの HTML で、社内スレッドに添付 → 副支配人がブラウザで開いて最終合否と電子印 → 再出力、の往復ができます。

2026-10-14 に**面接に特化**しました（副支配人の指示「面接までの経緯はクリアしているので省いてよい」）。面接前の入力・判定の機能と押印欄 1 つを削除し、押印欄は面接対応者・最終確認の 2 つです（削除した機能は `docs/HANDOFF.md` の「削除済み機能」、削除前のコードはタグ `full-mode-last`）。

## 使い方（配布）

1. `dist/toho-recruit-judge.html` を PC に置き、ブラウザ（Edge / Chrome）で開く
2. 左のメニュー「報告書の作成」で 3 ステップを進める（トップバーの画面名は「面接チェックリスト報告」、サイドバーの見出しは「手順」）
   1. **① 応募者** … 1 枚のカード・3 行だけ（氏名だけ必須。あとは分かる範囲で）。PC の画面（1280×800 以上）ならスクロールせずに「面接チェックリストへ進む →」まで見える
      - 1 行目: 氏名（必須）・年齢・性別・区分（高校1〜3年生／大学1〜4年生／大学院生／専門学校生1〜3年生／フリーター／主婦・主夫／ダブルワーカー／その他）。学生の区分のときだけ末尾に卒業予定年月
      - 2 行目: 面接日（既定は今日）・面接担当者（名簿から選択。③ の押印欄「面接対応者」の初期選択になる）・応募した求人（「通常」「短期」のボタン）
      - 3 行目: タクシー可否・料金（自由記述。例: 可・2,500円）・メモ（任意）
   2. **② 面接チェックリスト** … 台本の順に ① 勤務条件 10分 → ② 継続性・報連相 3分 → ③ 仕事内容の説明 10分 → ④ 集団行動特性 8分 → ⑤ 逆質問 最大10分（合否連絡を含む）。上部に ① で入れた属性を 1 行（氏名・区分・年齢・求人・タクシー・面接日・担当。読み取り専用・「応募者を編集」で ① へ）と目次（sticky。済・不一致・面接評価の点数をライブ表示）
      - **必須条件**（土日を含む週3日以上・5時間以上／指定繁忙期間すべて可）は 一致／不一致（未回答は「未確認」）。1 つでも不一致なら赤い案内が出て「⑤ 逆質問へ」で面接を打ち切れる
      - 説明は「説明済み」のチェック（※短期求人のみの項目は短期求人のとき強調）。【説明】【合否連絡】の見出しの右の「すべて説明した」で一括チェック（※短期求人のみ の項目は求人が短期のときだけ。もう一度押すと「すべて外す」）、質問は質問文を大きく表示してメモ欄に回答を書く、記入欄（土日いずれか／両日・出勤不可な繁忙・短期／長期の希望・契約開始日の希望・初回契約終了・OPEN／25時までの可否）
      - **確認事項／確認点**（7 項目）を ○△× と一言メモで評価し、最後に**面接者の総合判断**（採用／保留／不採用）と面接所見
      - 入力のチェックでは止めない（未入力は報告書に「確認事項」として出る）。「報告書へ進む →」
   3. **③ 報告書** … 開いた時点で判定し、A4 1 枚の「面接チェックリスト報告」の紙プレビュー（白地。ダークモードでも白。印刷と同じ等倍の文字で見せ、1280px・1366px など右サマリーの横に紙が入らない画面では右サマリーを紙の下に回す）を表示。その下に押印欄（**面接対応者／最終確認** の 2 つ。2 列）と「最終合否」、操作ボタン「🖨 A4 で印刷」「💾 報告書を保存（HTML）」。押印・合否を変えると紙プレビューも描き直す
3. 右のサマリーには 氏名・属性（区分・年齢・性別。短期求人ならそのチップ）・面接日・担当・必須条件（一致／不一致／未確認）・採点（○△× の集計と点数）・総合判断・結果・押印状況・最終合否・保存状態を出す
4. 「保存（HTML）」で応募者ごとに 1 ファイル。「読み込み」で続きから再開できる
   - ③ を開かずに ① や ② から保存・A4 印刷しても、その時点の入力で判定して報告書に結果を入れる（チェックリストが未入力でも上長最終判断要＋確認事項として出る）。③ を開くと同じ判定になる。読み込むと保存したステップ（①／②）から再開する
   - 総合判断が未入力のまま保存すると「（総合判断が未入力です）」の警告を出す（保存は止めない）
   - 2026-10-14 より前のファイル（v1・旧 10 項目の評価入りなど）もエラーなく読める。削除した機能のデータは読み込まず（toast で案内）、面接チェックリストの回答・押印（面接対応者・最終確認）・最終合否は引き継ぐ。旧い形式の記録は ② で開くので、面接チェックリストで評価し直す（回答と判定が入っている記録は ③ 報告書で開く）

### 結果（推奨）の決まり方

- 必須条件に 1 つでも「不一致」→ **不採用推奨**（台本どおり。設定 `checklist.mustFailResult` で「上長最終判断要」に変更可）
- それ以外は **面接者の総合判断のとおり**: 採用 → 採用推奨、保留 → 上長最終判断要、不採用 → 不採用推奨。総合判断が未入力なら上長最終判断要＋警告
- 必須条件の「未確認」は警告だけ（`mustUnknownResult = 'review'` で採用推奨に留めない）。総合判断の上限 `checklist.overallCaps` は厳しくしたときだけ効く（結果を下げる方向のみ）
- 確認点の ○△× は面接評価（○2・△1・×0 ＋総合判断 2/1/0、既定 16 点満点、帯 高 ≥ 70%・中 ≥ 40%）として報告書に載せる。結果は変えない（「採用」なのに × があれば警告 1 行）

  | 例（16 点満点） | 点 | % | 帯 |
  | --- | --- | --- | --- |
  | 全○＋採用 | 16 | 100 | 高 |
  | ○4 △3＋採用 | 13 | 81.3 | 高 |
  | ○4 △2 ×1＋採用 | 12 | 75 | 高 |
  | ○3 △3 ×1＋採用 | 11 | 68.8 | 中 |
  | 全△＋採用 | 9 | 56.3 | 中 |
  | ○1 △3 ×3＋保留 | 6 | 37.5 | 低 |

## 報告書（HTML）と最終合否

アプリの判定（採用推奨／上長最終判断要／不採用推奨）とは別に、最終確認者（副支配人）が「採用」「不採用」のスタンプで最終合否を記録します。

1. 面接者がアプリの ③ 報告書で押印欄「面接対応者」に電子印を押し、「報告書を保存（HTML）」→ 社内スレッドに添付
2. 副支配人がその HTML をブラウザで開く。常に**「報告書」表示**（A4 の紙プレビュー＋「最終合否」と押印欄）で開き、上部の「詳細」でヘッダー・応募者情報・面接チェックリスト（台本の全文）・採用可否判定・応募者の管理を表示する
3. 「最終合否」で担当者を選び「採用」または「不採用」を押す → 合否スタンプ（採用＝朱・不採用＝藍、日付と劇場名入り）が紙の結果ストリップの右端に出る。押印欄「最終確認」が未押印なら同じ担当者の電子印も自動で押される
4. 「押印を保存」で再出力 → スレッドに添付。ファイル名の末尾に `_採用` / `_不採用`（例: `応募者_山田_太郎_2026-10-10_採用.html`。押し直すと付け替え、「取消」で外れる）
5. 再出力したファイルをアプリの「読み込み」で開くと、合否・押印ごと ③ 報告書と右サマリー（例「採用・笹川」）に引き継がれる。合否が判定と食い違う（採用 × 不採用推奨など）ときは注記を 1 行出すだけで止めない

- 「取消」は合否だけを消し、自動で押した「最終確認」の印は残る（押印は押印欄の「取消」で消す）
- 担当者名簿は設定の「応募者の管理（押印）」で編集。合否の UI は同じ節の「最終合否（採用／不採用のスタンプ）」で ON/OFF・表示名・連動する押印欄・ファイル名の接尾辞を変えられる

## 印刷（A4 面接チェックリスト報告 1 枚）

- アプリ: ③ 報告書の「🖨 A4 で印刷」、② の「🖨 面接チェックリスト報告（A4）」、トップバーの「🖨 印刷」、ブラウザの印刷（Ctrl+P）のどれでも面接チェックリスト報告になる（判定が無ければ印刷の前に現在の入力で判定する）。設定・使い方の画面での Ctrl+P は画面全体の印刷
- 保存 HTML: 「A4 で印刷（1 ページ）」ボタン、または報告書表示のまま Ctrl+P。「詳細」を表示して Ctrl+P するとブラウザの既定の印刷（台本の全文を含む詳細）になる
- 中身（2026-10-14〜。副支配人「煩雑すぎて頭に入ってこない。わかりやすく、かつ1ページで」）: 誰を・どう判断し・何が気になるかを 10 秒で掴める **A4 1 枚の要約**。上から
  1. ヘッダー帯（面接チェックリスト報告・台本の版・劇場名・作成日）
  2. 応募者（氏名を大きく＋区分・年齢・性別・卒業予定／面接日・担当・応募した求人・タクシー可否・料金。空の項目は省く）
  3. **結果ストリップ**: 結果（採用推奨＝緑／上長最終判断要＝琥珀／不採用推奨＝赤。判定前は「未実施」）・総合判断・必須条件（すべて一致／不一致 n）・確認点（16/16点・○△× の数）、右端に最終合否（未押印は点線枠）。調整があればその下に 1 行（例「必須条件の不一致により「不採用推奨」に固定」）
  4. 必須条件（○一致／×不一致／－未確認・土日勤務可否・出勤不可な繁忙）｜勤務条件の確認（短期／長期の希望・契約開始日・初回契約終了・OPEN／25時の可否）
  5. 確認点 7 行（①〜⑤・名前・○△× の丸バッジ・メモ 1 行。未入力の行も出す）
  6. 面接メモ（記入があるものだけ。質問の回答は「短い名前：回答」で 2 行まで・面接所見・① のメモ）
  7. 説明・連絡 1 行（説明済み ① 4/4 ・ ② 3/3 …／合否連絡 採用時 ☑ ／ 不合格 ☐。※短期求人のみ の説明は求人が短期のときだけ数える）
  8. 押印行（面接対応者／最終確認）
- 台本の説明文・質問文・確認点の補足・空の記入欄は載せない。台本の全文（質問文・説明のチェック・記入欄・メモ・点）は保存 HTML の「詳細」の「面接チェックリスト」節に残る
- 必ず 1 ページ: 本文が A4 を超えたら自動で詰める（`.cl-compact` 本文 9px・面接所見は 10 行まで〔質問の回答は 2 行のまま〕→ `.cl-compact-q1` 質問の回答 1 行 → `.cl-compact-2` 質問の回答を省いて「詳細」を案内 → 最後は縮小〔縮小後に測り直す〕）。上限は押印欄の件数（押印行の段数。3 件まで 1 段）で決める。メモが「…」で切れたら「全文は保存 HTML の「詳細」表示に」の 1 行。紙プレビューも印刷と同じ見た目。白黒でも読める記号
- 回答が無くても印刷できる（白紙の台本として面接前に使える）

## 設定（劇場ルール）

設定画面は 5 節です。

1. **劇場情報**: 劇場名・アプリ名・バージョン表記・フッター
2. **応募者の属性**: 区分（「値|グループ」。グループは学生〔highschool / university / vocational。① に卒業予定年月の欄を出す〕か、それ以外〔other〕か）・性別・卒業予定年月の表示
3. **面接チェックリスト**: 判定（必須条件の不一致・未確認のとき・総合判断の上限・不一致のとき案内するセクション・面接評価の帯〔高・中・低〕の境界）・総合判断の見出しと表示名・ヘッダー（担当と連動する押印欄・応募した求人）・印刷（「詳細」に質問文を載せるか）・台本（版・ページの見出しと説明・セクション・ブロック・項目の文言と増減・並べ替え・既定に戻す）
4. **応募者の管理（押印）**: 押印欄 2 つ（面接対応者・最終確認）の表示名と説明・担当者名簿・手入力の可否・最終合否（ON/OFF・表示名・連動する押印欄・ファイル名の接尾辞）
5. **書き出し／読み込み**: プロファイル JSON の書き出し・読み込み・初期設定に戻す

- 結果の文言（`texts`）は画面に出さない（JSON の書き出し／読み込みでだけ変更できる）
- 設定はブラウザの localStorage（キー `recruit.profile.v1`、`schemaVersion: 2`）に保存。キーは `schemaVersion, meta, features, management, options, evaluation, checklist, texts` の 8 つだけ。他劇場・他端末へは JSON を書き出して読み込む
- 2026-10-14 より前の設定は開いたときに正規化して保存し直す（削除した機能のキーと廃止した押印欄 `initial` を落とす。旧い運用モードの設定だったときは 1 回だけ toast で案内）。v1 形式の JSON は移行せず既定の設定にする（「古い形式のため既定の設定を使います」）
- 応募者データはブラウザに残らない（保存した HTML のみが記録）

### ロゴ・名簿入りの版（公開リポジトリには入れない）

ロゴ（商標）と担当者名簿の実名は公開リポジトリに置かず、`recruit-system/local/`（.gitignore 済み）に置いてビルドします。

```
recruit-system/local/
  logo.png          ロゴ（logo.svg / logo.webp / logo.jpg も可。横 440px 程度の透過 PNG を推奨）
  logo-alt.txt      ロゴの代替テキスト（例: TOHO CINEMAS）
  managers.txt      担当者名簿。1 行 1 人「氏名|印字名|役職|等級」（設定画面と同じ形式。# で始まる行は無視）
```

`node build.js --local` で `local/dist/toho-recruit-judge.html` に出力します（公開版の `dist/` は書き換えません。`--out` で `dist/` を指定すると止まります）。ロゴはサイドバー（ダークモードでは白い台紙）と保存レポートの「詳細」表示のヘッダーに出ます。ロゴが無いときは劇場名の 1 文字のマーク（新）です。新宿のロゴは公式の EPS（TC_logo_1L.eps）を Ghostscript で PDF にし、`pdftocairo -png -transp -scale-to-x 440` で作りました。
- テスト（すべて exit 0 で合格）:

  ```
  cd recruit-system
  node tests/rules.test.js           # 単体テスト（Node だけで動く）
  ```

## 設計方針

- **ロジックとルールの分離**: `rules.js` は劇場名・しきい値・文言を一切持たず、`profile` を引数に受け取る
- **面接チェックリスト** = 台本は `profile.checklist`（セクション → ブロック〔must 必須条件 / fields 記入欄 / explain 説明 / question 質問 / rating 確認点 / notify 合否連絡 / note 注記〕→ 項目）のデータ。判定に効くのは must・総合判断だけで、rating は面接評価（点数・帯）として報告し、ほかは記録用。回答は `record.checklist`（項目 id をキーにした `values` / `notes`・`overall`・`header`）、保存時点の台本を `record.checklistDef` に残し、レポートは保存時の文言で出す。面接評価は `rules.interviewModel(profile, cl)`、判定は `rules.evaluateScript`（総合判断が基準）
- **ステップの内部キー** = `state.step`・`data-step`・`record.step` は 1 / 3 / 4（表示は ①②③）。旧レコードの 2 は ① に読み替える
- **保存形式** = 人が読める HTML レポート＋ `<script type="application/json" id="recruit-record">` に元データ（`schemaVersion: 2`。キーは `kind, schemaVersion, savedAt, profile, step, applicant〔6 キー〕, checklist, checklistDef, interviewNotes, management, decision, judgment`）を埋め込み。見た目を変えても読込が壊れない。レポート本体はアプリと同じデザイントークンで、A4 印刷にも対応（`storage.js` の `reportCss`・`checklistSheetCss`）
- **後方互換** = 旧プロファイルは `storage.normalizeProfile`（許可したキーだけ組み立てる）、旧保存ファイルは `storage.normalizeRecord`（応募者 6 キー・廃止した押印欄 `initial` を外す・旧い形式の印を返す）で読む。`PROFILE_KEY`・`schemaVersion`・面接チェックリストの項目 id は変えない
