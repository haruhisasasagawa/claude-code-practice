## 0. 目的・決定事項・原則

### 0-1. 副支配人の指示（2026-10-18）

「各ページ、確かめること、聞くこと、話すことみたいな感じで横並びになっているが境目がわかりにくいから UI は何かしら変更が必要です。また各種ヒアリングや確認ボタンの位置にばらつきがあるのでわかりにくい。もう少し全体的に統一感を。UI の見直しとデザイン力の向上をお願い致します。」

### 0-2. 選択（AskUserQuestion の回答。変更不可）

| 論点 | 決定 |
|---|---|
| 面接の各段階の形 | **縦一列の 3 枚のカード**。「話すこと」「聞くこと」「確かめること」をそれぞれ色つきの見出し帯のあるカードにして上から順に並べる。ボタンは全部右端の同じ列にそろえる |
| 順番 | **全段階で 話す → 聞く → 確かめる**。一致／不一致や選択のボタンはいつも最後のカード（［次へ］のすぐ上） |
| 配色 | **落ち着いた紺を基調に統一**。主ボタン・見出しを紺で。色は意味のある所だけ（緑＝一致・○、琥珀＝注意、赤＝不一致・×）。TOHO の赤はロゴだけ（警告の赤と混ぜない） |

### 0-3. 原則（迷ったらここに従う）

1. **業務ツールとして、落ち着いて・読みやすく・迷わない**ことを最優先にする。装飾の色（グラデーション・左の色の縦線・太い線）は足さない。**色を使うのは見出し帯と意味の色だけ**。区切りは余白・カードの枠・帯の下の線で見せる。
2. **色は意味のある所だけ**。紺＝操作・現在地・見出し・進み具合（済み ✓）／緑＝一致・○・採用・良い点（4〜5 点）／琥珀＝注意・未入力・一部だけ／赤＝不一致・×・不採用・1 点・エラー。それ以外は中立の灰色。話す・聞く・確かめるを色で塗り分けない（アイコンと名前と順番で分ける）。
3. **操作は右の列**。項目の行は「左にラベル・右に固定幅（280px）の操作列」。一致／不一致・選択肢・入力欄・○△×・1〜5・採用／保留／不採用、**見出し帯のトグル［説明した］［伝えた］も**この列に入り、左端も右端もそろう。
4. **紺の地（塗り）は、主ボタン・今の段階（チップ・段階の番号・サイドバーの今の手順）・選んだ選択肢だけ**。1 画面の主ボタンは 1 つ（下の操作行の右端）。トグルのオン・済みの印・案内は淡い紺（枠と文字が紺）にする。
5. **文字は 6 段階（12・13・15・17・20・24px）・太さは 2 つ（400・700）**。Windows の BIZ UDPゴシックは 400 と 700 しかないため。選んだ状態や見出しを太さだけで区別しない（塗り・色・線・位置と組み合わせる）。台本の読み上げる文（話すこと・質問）は 17/400。
6. **余白は 4 の倍数**（`--sp-*`）。カードの間 24px、カードの中の左右 20px・上下 16px、行の上下 12px。カードの間は、カードの中の区切り（12〜16px）より必ず広い。4 の倍数でない値は 1-5 の例外の表（位置合わせ・部品の内側の寸法）だけ。
7. **アイコンと番号は部品**。アイコンはインライン SVG（絵文字・記号の文字を使わない）。段階・手順の番号は丸の部品 `.nb`（丸数字の文字は台本の文・用紙・説明の文の中だけ）。
8. **同じものは同じ部品・同じ位置**。ボタン・入力欄・セグメントボタン・カード・行の高さ・角丸・余白を画面ごとに変えない。下の操作行のボタンは 4 つの画面（準備・面接・評価・報告書）と設定で同じ座標。

## 6. アクセシビリティ

- **コントラスト**: 1-3 の表のとおり。試作の全画面で自動で確かめた（0-4）。
- **フォーカス**: すべての操作に 2px の `--focus` の輪（offset 2）。セグメントボタンは輪が隣に隠れないよう `z-index`。見出し（`#ivStageH`）はプログラムでフォーカスするだけで輪を出さない（いまどおり）。
- **固定の帯が Tab の移動先を隠さない**: scroll-padding（`--flow-top-h`・`--flow-foot-h`。JS で測る）＋ `focusin` で帯・操作行に掛かったら `scrollIntoView({block:'nearest'})`（3-11）。
- **キーボード**: Tab の順＝見た目の順（段階の見出しから 話す〔「一部説明しなかった」→［説明した］〕→ 聞く → 確かめる → 操作行の主ボタン。e2e E19 (5)）。見出し帯のトグルは Space・Enter で押せる。サイドバーの手順も Enter・Space（まだ進めない手順は動かない。E23 (4)）。Ctrl＋Enter で［次へ］・人物像の数字キー（いまどおり）。面接のボタンの上の Enter・Space の押しっぱなし（キーリピート）は捨てる・キーボードで［次へ］を押して未確認の必須条件で止まったときはフォーカスを［次へ］に残す（4-3 の 10。E24 (10)）。
- **色だけに頼らない**: 選んだ選択肢は塗り（白との明るさの差）＋`aria-pressed`、トグルは地・枠・アイコン（○ → ✓）・文字（「一部…（2/3）」）、未入力は地の色＋バッジ「未入力」、不一致の行は地の色＋押した［不一致］、段階の状態はチップの ✓・文字（未確認・省略可）・枠の形（点線）、結果はバッジの文字。
- **読み上げ**: カードは `<section aria-labelledby>`、帯の題は `h3`、段階の名前は `h2`。セグメントは `role="group"`＋`aria-label`（項目の全文）。アイコンと `.sym` は `aria-hidden="true"`。番号の部品は中の丸数字の文字（①）が読まれ、数字の `::before` は代替テキストを空にする（`content: attr(data-no) / ""`）。チップは `aria-label` に番号・名前・状態（名前を隠したときも）。
- **動き**: 色の変化だけ。`prefers-reduced-motion` で止める。
