# コンセッション事前準備数ツール（v5.2）

TOHOシネマズ新宿のコンセッション（飲食売店）向けに、ピーク前の商品準備数（作る数）を
過去の購買率から算出するExcelツール。TOHOの営業週（金曜開始）に対応。
v5で時間帯係数の較正シート（係数算出・係数貼付①〜④）を本体ワークブックに統合。
v5.1で「商品別の波」（商品ごとの時間帯パターンの実測と作る数への適用）を追加。
v5.2で調整倍率を廃止してシンプル化（係数は「商品別の波が出る商品はその実測係数、
出ない商品は時間帯係数」の商品ごと置き換えのまま）。

- 成果物: `TOHO新宿_コンセッション準備数ツール.xlsx`（未入力テンプレート・全機能入り1ブック）
- 生成スクリプト: `build_tool.py`（openpyxl。CSVを渡すと入力済みサンプルも生成可能）
- 較正モジュール: `build_calib.py`（係数算出・係数貼付シートを本体へ追加する。単体実行はしない）
- 検証スクリプト: `verify_tool.py`（CSVからPythonで独立集計した期待値とExcelの計算結果を突合）
- 店舗版の更新: `upgrade_v2.py`（店舗版ver1.1に ⑤事前準備率・保持時間/作るタイミング・⑥ピーク時間・作る順を当てて ver2.0 にする。→「v2.0 更新スクリプト」）
- 店舗版の検証: `verify_v2.py`（`--products auto` で店舗版の商品名、`--mso1〜4` で係数算出・商品別の波まで厳密突合）
- 仮数値サンプル: `make_sample_v2.py`（店舗版ver2.0に乱数合成のCSVと入力例を貼り込んだ配布用サンプルを作る。→「仮数値サンプル」）
- 調理時間シート: `add_cooking_sheet.py`（調理マニュアルの機器・個数別の時間を商品に名寄せして転記し、作る数から所要時間を出す。→「調理時間シート」）

※ 実売上CSV・実データ入りサンプル・店舗版ワークブックは店舗の実数を含むためリポジトリには含めない。
　`make_sample_v2.py` が作る「仮数値サンプル」は売上数・動員数・MSO明細をすべて乱数で合成した仮データなので
　店舗・社内で共有可（数値・日付・明細・劇場コード/劇場名は仮。登録商品名・営業時間の区切り・ロゴ・ブックの
　作成者情報は店舗版のまま）。生成には店舗版ver2.0が必要なため、サンプルxlsx・CSV自体もリポジトリには置かない。

## シート構成

| シート | 役割 |
|---|---|
| 使い方 | 3ステップの利用ガイド・凡例・注意点・較正の手順 |
| 準備数計算 | 参照期間(A/B)の購買率 × ピーク動員数 × 係数（時間帯／商品別の波） →「👉 作る数」 |
| 印刷用 | A4縦1枚の仕込み指示書（自動連動・チェック欄・記入欄付き） |
| 期間データ | 期間A（直近金土日）・期間B（前週 金〜木）の日付・動員数入力と商品別販売集計 |
| CSV貼付A / B | 本社集計「売上・在庫・原価」CSVを全選択コピー→オレンジのA4セルへ「値の貼り付け」するだけのシート |
| 係数算出 | 金曜4週分のMSO明細から時間帯5段階の係数候補を実測算出（月1回・任意） |
| 商品別の波 | 登録商品ごとの時間帯パターン（構成比・商品別係数・判定）を自動算出 |
| 調理時間 | 調理マニュアルの転記（機器・個数別の時間・一度に最大）と作る数からの回数・所要時間。店舗版に `add_cooking_sheet.py` で追加 |
| 係数貼付①〜④ | MSO商品CSV（注文明細・金曜1日分）を1週ずつ貼る較正用の貼り付けシート |

## 計算ロジック

- 購買率 ＝ 参照期間の販売数（CSVの「売上数」列をSUMIF集計） ÷ 参照期間の動員数合計
- 販売予測数 ＝ ピーク動員数 × 購買率 × 係数（端数処理はテンプレートが切り上げ／店舗版ver2.0は切り捨て）
- 作る数 ＝ 販売予測数 × ⑤事前準備率（同じ端数処理。画面の販売予測数から計算するので手計算と一致する）
  - ピーク動員数 ＝ ⑥ピーク時間に入れた時間帯に始まる回の合計動員数
  - 係数 ＝ 商品別の波の実測係数が出る商品はそれ、出ない商品は時間帯係数
    （商品ごとの置き換えで、1商品に両方が同時に掛かることはない）
  - 時間帯係数 ＝ 5段階の時間帯プリセット（既定は 朝一6:45〜11:00／昼ピーク11:00〜14:00／夕方14:00〜18:00／夜ピーク18:00〜21:00／レイト21:00〜翌2:00。区切りは係数算出!C4:H4 で変更）＋平常。枠は最大7。係数は係数算出の実測を自動採用し、実測が無い帯は既定値
- 参照期間: 期間A（直近金土日）／期間B（金〜木）／期間平均（A+B合算10日間）をドロップダウンで切替。
  比較期間（A選択時はB、それ以外はA）の購買率を参考列に表示
- 期間の日付は貼られたCSVの「対象期間開始/終了」から自動表示（入力不要）
- 商品名: 貼られたCSVの商品名から数式で自動抽出したリストのプルダウンで選択（先出順・手入力も可）
  - ドリンク類・調味料・ＳＥＴ作品コンボ・引換券・包材は既定でプルダウン対象外（小分類名の除外リストで編集可。集計からは除外されない）
- 商品枠は最大20、CSV貼付は各期間 最大1000行

## 時間帯係数の較正（係数算出・係数貼付①〜④）

- 係数貼付①〜④に金曜4週分のMSO商品CSV（注文明細・秒単位の時刻つき・金曜1日分で出力・
  最大30,000行/シート）を1週ずつ貼ると、係数算出シートが5段階の係数候補を自動算出
  （貼った週だけで平均。4週未満でも動作）
- 係数候補 ＝ 帯の1時間あたり販売個数 ÷ 全帯平均の1時間あたり販売個数。
  時間の区切り（既定 8:00/11:00/15:00/18:00/21:00/閉店22:00）は係数算出シート上で編集可
- 閉店時刻は基本22:00。同日閉店（21時以降の時刻）と翌日閉店（24:00〜26:00。26:00＝翌2:00、
  翌2:00表記も可）を自動判別（内部のN4/O4で正規化）。レイト帯⑤の窓と帯長が閉店に連動。
  設定ミス・実態とのズレのガード: 区切りの外（開店前・閉店後）の販売は個数つきで⚠、
  閉店をレイト開始より前に設定した場合も⚠、翌開店を超える入力（33:00等）は開店で
  クランプして二重計上を防ぎ⚠、翌日閉店設定なのに22時以降の販売が0個の週（レイト営業の
  無い金曜の混入疑い）も⚠。これらの時刻系⚠は商品別の波の適用中（M9=1）に準備数計算
  B9・印刷用へも連動（生成時は `--close 26:00` などで初期値を指定可能）
- 集計ルール: セット親・注文取消・払戻は除外して実個数を集計。複数日が混在したCSVは
  先頭の日付だけを集計して状態表示に⚠（対象日はS3で手動上書き可）。金曜以外は※表示
- 候補は「準備数計算」プリセット表の右の実測候補列（K4:K8）にも自動表示。
  採用はプリセット表のJ列で自動（店舗版ver2.0は J＝IF(ISNUMBER(K),K,既定値) の式。手入力すると自動更新が止まる）
- シート保護（パスワード無し）: 貼り付けシートは貼り付け領域（ヘッダー行4行目〜データ列）と
  設定セルのみ編集可。シート全体を選択した貼り付けや行削除でAE/AF等の内部式が消える事故を
  Excel側でブロック。係数算出（時間の区切りC4:H4と対象日のみ編集可）・商品別の波（しきい値のみ編集可）も
  保護し、並べ替えによる行対応崩れも防止。これは `build_tool.py` が作るテンプレートの話で、
  店舗版 ver2.0 は全13シート＋ブック構成を保護する（→「ブック全体のロック」）
- 誤操作ガード: 別種CSVの誤貼付・貼付位置ズレ・行削除によるヘルパー式の破損は
  各貼付シートの正常フラグ（AD3: ヘッダー照合＋式の生存数チェック）で検知し、
  その週を集計から自動除外して状態表示と係数算出のB23に⚠。30,000行超の貼付も⚠

## 商品別の波（商品ごとの時間帯係数）

- 「商品別の波」シートが、登録20商品それぞれについて帯別の販売個数（係数貼付①〜④の
  有効週合計・非表示のP〜T列）→構成比（1日の売れ方の推移をデータバーで可視化）→
  商品別係数（帯の1hあたり個数÷その商品の1日平均ペース・0.05刻み）を自動算出
- 準備数計算の「④ 商品別の波」を『使う』（既定）にすると、作る数の係数が商品ごとの
  実測係数に置き換わる（その商品には時間帯係数は掛からない）。
  適用値は「商品係数」列に表示（—＝時間帯係数）
- 自動フォールバック: 合計個数がしきい値（既定30個・商品別の波!D3で編集可）未満の商品は
  「⚠少データ」、MSO側に同名が無い商品は「該当なし」、選択した帯の個数が0の商品や
  0.05刻みの丸めで0.00になる極小係数の帯も
  全体の時間帯係数で計算（作る数が無警告で0になるのを防ぐ）。
  時間帯プリセットが①〜⑤以外（平常など）やMSO未貼付のときも全商品が時間帯係数
- 帯の対応はプリセット名の先頭の①〜⑤マークがキー（行位置に依存しないため表の
  並べ替えに頑健）。改名時もマークは残すこと（消すとその帯は全体係数になり赤警告）
- 商品名の照合は完全一致（実データでは登録20商品すべてMSO側と一致を確認済み）。
  帯の区切り・帯の長さは係数算出シートの設定に連動（区切りが逆転した帯は自動除外）

## 入力ミスへのガード

- CSVの日数チェック（期間A=3日/期間B=7日想定、✔／⚠）、金曜開始チェック、別期間行の混在検知、
  古いデータの検知（終了日が10日以上前（今日−終了日 > 9）なら⚠）
- 計算シート上部に赤字警告（印刷用にも連動）: CSV未貼付 / 期間不一致 / 動員数不足 /
  商品名重複 / ピーク動員数未入力 / 時間帯係数0・×50%〜×500%の範囲外
- 動員数ゼロのときは購買率に「要確認」、作る数に「—」を表示
- 商品名の重複は赤ハイライト。プリセット名が不正でも係数は×100%（1.0）にフォールバック
- 入力規則のエラーアラート有効（動員数の数値限定を含む）。全シートA4印刷設定済み

## v2.0 更新スクリプト（店舗版への拡張機能の追加）

店舗が手直しした ver1.1 のワークブックはテンプレートから分岐しているため、作り直さずに
`upgrade_v2.py` で読み込んで拡張機能だけを当てる（店舗のカスタマイズ＝時間帯設定の自動化・
営業時間・切り捨て・商品登録・文言はそのまま残る）。

```bash
python upgrade_v2.py <店舗版ver1.1.xlsx> <出力ver2.0.xlsx>
python verify_v2.py <再計算済みxlsx> --csv-a ... --csv-b ... --att-a ... --att-b ... \
    --peak 1200 --mult 0.6 --rate 80 --view 直前に作るもの --ht 10,45,,30,... --manual 0:高 --thr 30 \
    --peak-start 17:30
# --manual の添字は0始まり（0＝期間データB14の1商品目）。--peak-start は⑥ピーク開始（既定17:30。
# O5が未入力のブックは --peak-start "" を渡す）
# 店舗版の商品名で検証するときは --products auto、MSO貼付ありは --mso1〜4 に貼ったCSVを渡すと
# 係数算出・商品別の波・商品係数の適用(販売予測数)まで厳密に突合する(--mso だけなら近似。--mult は不要)
python verify_v2.py <再計算済みxlsx> --products auto --csv-a ... --csv-b ... --att-a ... --att-b ... \
    --peak 1200 --rate 80 --ht ... --mso1 金曜1週目.csv --mso2 ... --mso3 ... --mso4 ...
```

追加される機能:
- **⑤ 事前準備率**（準備数計算!D8・整数%・既定100・1〜200）: 「販売予測数」（従来の作る数）に
  率を掛けた「👉 作る数」列を追加。印刷用は作る数を出し、見出しに率を表示
- **保持時間・作るタイミング**: 期間データに 保持時間(分)・タイミング(手動) の入力列と基準値（E12・既定30分）。
  保持時間が基準以下なら「直前」（持ちが短いのでピーク直前に作る）、長ければ「先に」（先に作っておける）、未入力は「—」（手動で上書き可。旧表記の「高」「低」を入力してあっても効く）。
  準備数計算に 保持時間・作るタイミング 列（自動）
- **⑦ いま**（準備数計算!O8・⑥のすぐ下）: 今の時刻を手入力すると、印刷用の**画面だけ**に「いつ作る」列（K列・
  印刷範囲 A1:I28 の外）が出る。⏳ あと○分／▶ 今すぐ／⚠ ○分 足りません／⚠ ピーク開始を過ぎています。
  紙の見出し（B4）には「いま ○:○○ 時点」を刷る。空欄なら列は空になり、紙もこれまでと同じ
  - `NOW()` は使わない。揮発性で開くたびに変わり、刷った紙が何時の状態か分からなくなるため（手入力・刷る直前に更新）
  - 時刻の引き算は `MOD` で折り返さない。折り返すと「30分の遅れ」が「あと23時間30分」に化ける。
    翌日にまたぐピークは ⑥ に `24:30` のように24時間超えで入力する運用（閉店時刻と同じ書き方）
  - ピーク開始と12時間以上離れていたら「前回の値が残っていませんか」と ※ を出す（打ち忘れガード）
  - 判定の基準: 保持時間があれば「開始目安（ピーク開始 − 保持時間）まで あと○分」、
    保持時間が未入力の商品は「ピーク開始 − 調理の目安」で余裕を出す（保持時間が未入力でも死なない）
- **⑥ ピーク時間**（準備数計算!O5/O6・入力ブロックの右）: ピーク開始を入れると商品ごとの
  「仕込み開始(目安)」＝ピーク開始 − 保持時間 を準備数計算Q列と印刷用に表示
  （保持時間が長い商品ほど早く、短い商品ほど直前）
- **印刷用の並び＝作る順**: 常に保持時間の長い順（先に作って持たせられるものから。短いものは
  ピーク直前。未入力は最後）に並べ、上から「作る順」の番号を付ける。表示切替（G2）で
  直前に作るもの／低のみに絞り込み。開始目安・作るタイミング列を追加。並び順は準備数計算の非表示
  L列のキー（(10000−保持時間)×100＋行）を SMALL で拾う。A4縦1枚の印刷設定を明示的に固定
- タイトル帯・説明行は広がった表幅（Q列）まで伸ばし、店舗ロゴも帯の右端へ（警告行は非表示M列の
  ヘルパー式を結合で消さないよう元の幅のまま）
- **バグ修正**: 店舗版で期間A状態表示をG4→B7へ移した際に準備数計算の警告・比較期間判定が
  旧G4を参照したままだった箇所をB7へ付け替え。事前準備率の未入力⚠を追加
- 検証: `verify_v2.py` は CSV から独立計算した 販売予測数／作る数／作るタイミング／印刷用の並びを突合
  （表示切替3種・率100/80/120/0/未入力・期間ACSV破損・MSO込み・ピーク未入力の9変種で確認）

### 仮数値サンプル（`make_sample_v2.py`）

店舗に配る「入力済みサンプル」を実データなしで作る。売上・在庫・原価CSV（期間A=直近金土日・
期間B=前週金〜木）とMSO商品CSV（金曜4週分）を決まった乱数で合成し、店舗版の登録商品名のまま
貼り込む。動員数・ピーク動員数・保持時間・タイミング（手動）の例・メモ・⑥ピーク時間・事前準備率（例として80%。
100%だと販売予測数と作る数が同じ値になり効果が見えないため）も入れ、全シートの説明行に
「【サンプル：数値はすべて仮の値です】」、印刷用のタイトルに【サンプル】を表示する。

```bash
python make_sample_v2.py <ver2.0.xlsx> <サンプル.xlsx> [--csv-dir <CSV出力先>] [--sunday 2026-09-13] [--no-label]
python <xlsxスキルのrecalc.py> <サンプル.xlsx>                       # LibreOfficeで再計算
cd <CSV出力先> && python <repo>/verify_v2.py <サンプル.xlsx> $(cat verify_args.txt)   # 生成時の引数で厳密検証
```

- `--csv-dir` 省略時は出力xlsxと同じフォルダの `sample_csv/`。`--sunday` は期間Aの最終日（日曜以外はエラー。
  省略時は直近の日曜）。ツールの「古いデータ」通知（今日−終了日 > 9）は期間B側の終了日が先に引っかかるため、
  生成に使った日曜の翌日曜から準備数計算・印刷用に「※ 古い可能性」の通知が出る（計算は継続。使い方シートの
  説明行にその日付を明記し、完了メッセージにも印字する）。配る直前に作り直すのがよい
- 合成データの設計: 商品ごとに購買率・保持時間・時間帯別の売れ方（チュリトスは夕〜夜、ホットドッグは朝〜昼寄り
  など）を変えて「商品別の波」が見えるようにし、1商品（レモン＆ラムネ）は4週合計30個未満にして
  「⚠ 少データ → 全体係数」の例を出す（メモにも明記）。手動のタイミング「直前」の例（シナモンシュガー）とメモの例も入れる。
  除外小分類（ドリンク・包材など）の行もCSVに含め、プルダウンの絞り込みが分かる。営業時間・帯の区切りは
  店舗版の係数算出!C4:H4 から読む。劇場コード・劇場名は仮の値（0000・サンプル劇場）、支払先・作品名も
  「サンプル〜」で、商品コードは商品名から決めるので売上CSVとMSO CSVで一致する
- 出力CSV（`sample_periodA_*.csv` / `sample_periodB_*.csv` / `sample_mso_week1〜4_*.csv`、cp932・
  ヘッダー付き）はそのまま貼り付け練習に使える。`sample_params.json` と `verify_args.txt` は検証用
  （CSVは相対パスで書くのでフォルダごと移動してよい。配布物には含めない）

### 調理時間シート（`add_cooking_sheet.py`）

調理マニュアル（「調理時間一覧」シート: 商品／調理機器／条件／1個〜10個の時間／備考）を読み、
店舗版 ver2.0 に「調理時間」シートを追加する（期間データの次のタブ。使い方にも案内を1行足す）。
再実行するとシートは作り直される（手修正は消える。使い方の案内行は重複しない）。

```bash
python add_cooking_sheet.py <ver2.0.xlsx> <調理マニュアル.xlsx> <出力.xlsx> [--csv 売上A.csv 売上B.csv] [--sample-label]
```

- 上段の商品表（30行）: 登録商品（期間データ!B14:B33）を先頭に、売上CSVの食品カテゴリ（ホットドッグ・軽食系フード・
  調理系スイーツ・その他フード）の商品名からマニュアルの項目に名寄せできたものを続けて並べる（残りは新商品用の空き行。
  30行を超える候補は落として警告）。`--csv` を省略するとブック内の CSV貼付A/B に貼られた商品名を候補にする。
  「ＴＣ用」「テナント用」「廃棄計上用」の名前は候補から外す。商品名はプルダウン（`商品リスト`）
- 列: 商品名｜マニュアルの項目（参考・計算には使わない）｜調理機器・条件・一度に最大・回転の間隔（入力）｜
  作る数・回数・所要時間・保持時間（自動）｜照合・備考｜1〜10個の時間（秒・入力）。
  作る数は準備数計算の👉作る数を商品名で拾い（未登録は「未登録」）、回数 ＝ ROUNDUP(作る数 ÷ 一度に最大)、
  所要時間（分・1台）＝（回数 × 「一度に最大」の個数のときの時間 ＋（回数−1）× 回転の間隔）÷ 60。保持時間は期間データから。
  所要時間が保持時間より長い行は赤い背景（1台では保持時間内に作り切れない目安）
- 合計は「単純合計（機器が違えば並行できる）」と「機器ごとの段取り」。**台数が効くのはここだけ**で、
  商品ごとの所要時間（J列）と印刷用の「調理の目安」は台数に関係なく1台で作りきる分数のまま
- 機器ごとの段取りは同じ機器の商品を**順番に作る**前提で、2つの数を並べて出す:
  - **1台なら（G列）** ＝ 同じ機器の所要時間をそのまま足した分数（上限）
  - **ふさがる時間（J列）** ＝ `MAX(一番長い1回ぶん, 1台なら ÷ 台数)`（下限）
  台数で手分けできるのは「回」の単位までで、1回ぶんの調理は分けられないため、台数をいくら増やしても
  一番長い1回ぶんを下回らない。実際の時間はこの2つの間に入る。
  例: レンジ1台でポップチキン10分（1分×10回）＋スナックじゃが2分（0.67分×3回）→ 1台なら12分・ふさがる時間12分。
  3台なら ふさがる時間4分（回を分散できる）。一方チュリトス（1回20分×2回＝40分）＋チョコ4分 は
  10台にしても **20分**（1回20分は割れない）。旧版の「合計÷台数」は10台で4.4分と出ていた
- 機器名の照合は `SUMIF` ではなく `SUMPRODUCT(範囲=機器名)` の完全一致。SUMIF は Excel だと機器名の `*` `?` が
  ワイルドカードとして効いてしまい、LibreOffice と答えが変わるため
- 保持時間の超過は2段階: 「ふさがる時間」で超えるなら **⚠**（手分けしても間に合わない）、
  「1台なら」でだけ超えるなら **※**（手分けできれば間に合う）。機器名が2行に重複していると照合行が負になるので
  「同じ機器名が2行あります」と出す。調理時間が出ていない商品が混じっていれば件数を注記する
- マニュアルの機器名にある出力（「電子レンジ 1500W」の 1500W）は機器の違いではなく設定なので、機器名から外して
  条件の列に入れる（`冷凍／1500W`）。同じレンジで作る商品が1つの機器としてまとまり、台数を1か所で入れられる
- 台数は「同じように使える台数」。**専用機**があるときは台数をまとめず、機器名を分けて1台ずつにする
  （例: チョコの行の調理機器を「専用チュリトスオーブン（チョコ専用）」にして、機器ごとの合計の空き行に同じ名前を足す。
  空き行は3行用意）。逆に**同じ機械で設定だけ違う**とき（電子レンジの1500W／1800Wなど）は機器名をまとめて台数を入れる
- 名寄せは `MATCH_RULES`（マニュアルの項目名 → 含まれるべき語）で行い、確からしさを備考に示す:
  「名寄せ: 名前一致」／「❓ 名寄せ: キーワード推定（要確認）」／「⚠ 名寄せ: 先頭文字の推定（要確認）」（MATCH_RULES に無い
  項目は正規化した先頭4文字で仮に拾う）。同じ項目に複数の機器があるときは先頭の機器を転記して
  「⚠ 機器は要確認（他機種の時間）」を付ける。マニュアルに無い商品は「⚠ 該当なし → 手入力」。
  ❓⚠ は条件付き書式で色が付く。マニュアルに項目が無いCSVの食品は表の下に列挙する
- マニュアルの読み取り: 「40〜50秒」は上限で転記して備考に明記、「調理不可」は「—」、読めない表記は「?」と警告、
  「一度に最大2本まで」から最大、「連続調理は5分程度空ける」から回転の間隔、「（イレギュラー時）」は同じ商品の別機器扱い。
  下段にマニュアルの原本を転記（参考）。マニュアル自体はリポジトリに置かない
- `verify_v2.py` は調理時間シートがあれば 作る数・保持時間の連動、回数、所要時間、単純合計、機器ごとの合計（台数で割る）を突合
- ガード: 商品名の重複（条件付き書式＋合計行の⚠）、機器名が空欄・表記違いで機器ごとの合計から抜けた作る数の照合行、
  台数が未入力/数値でないときの注意、機器で作り切る時間がその機器の一番持ちの短い商品の保持時間を超えるときの⚠
- 所要時間はまだ 仕込み開始（目安）＝ピーク開始−保持時間 には入れていない（入れ方は店舗と相談）

### ブック全体のロック（`seal_protection.py`）

「入力していい場所以外は触らせない」ための保護。`upgrade_v2.py` / `add_cooking_sheet.py` /
`make_sample_v2.py` が出力時に `lock_workbook()` を通し、**全13シート＋ブック構成**を保護する。

- 編集できるのはこれだけ（`upgrade_v2.INPUT_CELLS` と調理時間シートの入力列）:
  - 期間データ: 動員数（C6:E6 / C10:I10）・期間の選択（E12）・商品名（B14:B33）・保持時間とメモ（E14:K33）・除外リスト（B37:B48）
  - 準備数計算: ①〜③の設定（D4:D8）・⑥ピーク時間（O5:O6）
  - 印刷用: 表示切替（H2）
  - 係数算出: 時間の区切り（C4:H4）と対象日（Q3/S3）
  - 商品別の波: しきい値（D3）
  - 調理時間: 商品名・調理機器・条件・一度に最大・回転の間隔・1〜10個の時間・台数・備考
  - CSV貼付A/B・係数貼付①〜④: 貼り付け領域（**列スタイル**で解放してあるので、
    1000行/30000行の貼り付けは保護下でもこれまでどおり動く）
- それ以外のセルは書式変更・並べ替え・行列の挿入削除ごと禁止。Excel は書き換えようとすると
  「変更しようとしているセルまたはグラフは保護されているシート上にあります」と出す。
  Excel 上で動く AI アシスタント（Copilot 等）も同じ経路なので同じく弾かれる
- `--password` を付けると保護の解除にパスワードが要る（`upgrade_v2.py` / `add_cooking_sheet.py` /
  `make_sample_v2.py` / `seal_protection.py` 共通。省略時は保護のみ・解除は誰でもできる）
- **再計算のあとに必ず `seal_protection.py` を通す**。LibreOffice で開いて保存し直すと
  ブック構成のロック（lockStructure）が落ち、シート保護も `sheet="true"` だけに簡略化されるため、
  xlsx（zip）の XML を直接書き戻して保護を復元する（計算結果のキャッシュは保ったまま）

```bash
python seal_protection.py <xlsx> [<xlsx> ...] [--password PW]   # 再計算の直後に実行
python seal_protection.py <xlsx> --check                        # 書き換えずに確認だけ
```

- 保護は**Excelの操作を止めるもの**で、ファイルそのものの改変を防ぐ暗号化ではない。
  openpyxl などスクリプトで書き換えれば保護は迂回できるので、**数式のすり替えは
  準備数計算の整合チェックで検知する**: 非表示のI列が各行の 販売予測数・作る数 を
  その場で計算し直して表示値と突き合わせ、ズレた行数を M12 に集計、B9 に
  「⚠ 販売予測数・作る数が計算どおりでない行があります（n件）」と出す
- `verify_v2.py` はブック構成のロック・全シートの保護・代表セルのロック/解除、
  および M12＝0（改ざんなし）を検証する
